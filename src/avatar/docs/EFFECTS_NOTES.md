# エフェクト知見メモ

気分に連動するまわりのエフェクト（`Effects.tsx` の輝き・光の粒・どんより）を作った際の
失敗と解決策。**three.js のシェーダーで描く部分**がこのメモの範囲。モデルそのものの話は
[BLENDER_MODELING_NOTES.md](BLENDER_MODELING_NOTES.md) / [BLENDER_ANIMATION_NOTES.md](BLENDER_ANIMATION_NOTES.md) にある。
書き方の決まりは BLENDER_MODELING_NOTES の「このメモの書き方」と同じ。

---

## Blender 側か React 側か

| 症状 / 要望 | 解決策 |
|---|---|
| 光る・粒が舞う・煙が出るエフェクトを付けたい | **React（three.js）側で描く。** Blender のパーティクル・Emission・Bloom・シェーダーノードは glTF に載らず、書き出すと消える |
| 気分や色相で出し入れ・強さを変えたい | コード側に置く。出すかどうかは気分の表（`MOODS` の `glow` / `motes` / `gloom`）に持たせ、形は `Effects.tsx` が持つ |

## 光を「光」に見せる

画面の地が白に近い（カードもダッシュボードも明るい）ので、**光は地より明るくできない。**
明るさではなく、塗り分けで光に見せる。

| 症状 / 要望 | 解決策 |
|---|---|
| 光の粒が虫（コバエ）に見える | 粒を**全部同じ向き**に動かす（下から上へ、同じ向きに回りながら）。生まれるときと消えるときは必ずフェード。ばらばらに漂う点（drei `Sparkles`）は虫に見える |
| 光が「色が付いている」ように見える | **明るさに応じて色 → 白へ寄せる。** 本物の光は明るい所ほど白く飛び、色は外側のにじみにしか残らない。全体を1色で塗ると絵の具に見える |
| 芯を白くしたのにまだオレンジが強い | 芯の白さとは別問題。**にじみの色そのものを淡く（彩度・明度とも上げて）する。** 濃い山吹色のままだと、外側がオレンジの輪として残る |
| にじみを淡くしたら見えなくなった | 淡くしすぎると白地に溶ける。色は淡いまま、にじみの濃さ（アルファ）を少し戻す |
| 粒がぼやけた丸にしか見えない | **2段重ね**にする。小さく強い芯（`exp(-r²·16)`）と、広く淡いにじみ（`exp(-r²·2.6)`）。ブルームの代わりになる |
| からだを光らせたら黄色く塗ったように見える | 発光（emissive）の色を金色ではなく**白に近い暖色**にする。色はそのままで、からだが明るく飛んで見える |
| 光の色をアバターの色相に合わせたい | **合わせない。** 背景のアクセント色が色相に連動しているので、同じ色相で塗ると背景に溶ける |
| 後光の板の四角い形が見える | 板をひよこの少し後ろに置き（`Billboard` の中で z を下げる）、奥行き判定でひよこの手前側に隠す。光は輪郭のまわりにだけ見える。ふちは板の端のずっと手前で消す |
| 粒がでかい・多くてうるさい | 見た目の「うるささ」は数と大きさでほぼ決まる。光芒（十字）は大きい粒だけに付ける |
| 輝きと光の粒の区別がつかない | **1つの要素は1つのエフェクトだけが持つ。** 輝きは後光とからだの発光だけ、粒は光の粒だけ。両方に粒を入れると見分けられない |
| 加算合成（AdditiveBlending）で光らせたい | **不可。** キャンバスは透明で地が白いので、足しても白以上にならない。通常の合成で塗り分ける |

## どんより（暗いエフェクト）

| 症状 / 要望 | 解決策 |
|---|---|
| 雨雲・縦線（漫画の記号）が安っぽい | **記号を置かない。** 貼り付けた絵に見える。光の粒の裏返しとして、暗いもやが垂れ込めて沈んでいく形にする |
| 暗い小さな粒が虫・ごみに見える | 暗い点にしない。**大きく淡い煙のかたまり**にして、もやの一部がちぎれて落ちるように見せる |
| 沈む粒が雨や雪に見える | 光の粒よりずっと遅くする。左右にふらふら揺らす |
| もやが平らな板のむらに見える | **domain warping**（ノイズでゆがめた座標でさらにノイズを引く）。うねりが出て煙に見える |
| もやに四角いむらが透ける | fbm の段ごとに座標を**回転させる**（`mat2(0.8, 0.6, -0.6, 0.8)`）。回さないと格子が揃う |
| もやの解像度が粗く見える（引き伸ばした画像のよう） | 3つ重なっている。**値ノイズをやめて勾配ノイズ**にする（5次補間）／段を増やす（4 → 6）／`smoothstep` の幅を狭めて煙のふちを締める |
| 白地に薄い暗色を重ねると濃さが段々になる（バンディング） | アルファに画素ごと ±0.5/255 のディザを足す（`hash(gl_FragCoord.xy)`） |
| 丸いぼかしの粒（ポイントスプライト）が粗く見える | 粒の中にも同じノイズで筋を入れ、ふちをちぎれさせる |

## three.js / r3f のハマりどころ

| 症状 | 解決策 |
|---|---|
| ポイントの大きさ・時間が変わらない（粒が1〜2px、止まったまま） | JSX の `<shaderMaterial uniforms={...}>` で渡すと、**`useFrame` で書き換えた値がシェーダーに届かなかった**（r3f 側で別の uniforms を持っているとみられる。原因の特定まではしていない）。`new THREE.ShaderMaterial({ uniforms })` を `useMemo` で作り、`<primitive object={mat} attach="material" />` で渡せば届く |
| 描いているはずの粒が見えない | まず `gl_PointSize` を定数（40 など）にして描画されているか切り分ける。出れば大きさの計算か、色が地に溶けているかのどちらか |
| ポイントの大きさを画面上で揃えたい | `gl_PointSize = size * uScale / -mv.z`、`uScale = 枠の高さ(px) * dpr * 0.5 * projectionMatrix[5]`。枠の大きさで変わるので毎フレーム入れる |
| 位置を GPU で作る粒が端で消える | `frustumCulled={false}`（ジオメトリの `position` はダミーなので境界が正しくない） |
| 色が暗く・くすんで出る | ShaderMaterial は色空間変換をしない。フラグメントの最後に `#include <colorspace_fragment>` |
| ひよこが向き直るとエフェクトまで回る | エフェクトを**歩く入れ物（位置＋向き）の外**に置き、位置だけを毎フレーム合わせる。前かがみの傾きも受けなくなる |
| 「視差効果を減らす」設定でも動く | 時間の uniform を進めず、止めた絵でもそれらしく見える時刻で固める |

## 確認の仕方

- **ログインなしで見比べる**：一時的に `preview-*.html` と小さな tsx を置き、`Avatar` に `effects` を直接渡して並べる。確認が済んだら消す（コミットしない）
- 本番に近い見え方はデバッグ画面の「エフェクト」カード。気分と別に出し入れできる
- 見た目の調整は**必ず白地の上で**見る。暗い背景では何でも光って見えて判断を誤る
- ヘッドレスのブラウザは dpr 1 で、拡大して細部を見るのが難しい。粗さの判断はシェーダーの作りから原因を切り分ける（ノイズの種類・段数・バンディング）
