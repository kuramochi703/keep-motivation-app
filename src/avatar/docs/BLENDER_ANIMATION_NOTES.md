# Blender アニメーション知見メモ

できあがったモデルにリグを入れ、アクションを作り、`.glb` に載せてアプリで
再生するまでの失敗と解決策。形を作るまでの話は
[BLENDER_MODELING_NOTES.md](BLENDER_MODELING_NOTES.md)。

**このメモの書き方**（何を書き、何を書かないか）と
**Blender MCP / 環境のハマりどころ**（作業ループの組み方・API の地雷・
成果物の残し方）はモデリング編と共通なので、そちらを読むこと。

---

## 方式

**スキニングしない。** メッシュはボーンに「オブジェクト親付け」する。

- three.js 側でスキンドメッシュになると、複製（`scene.clone`）がボーンを共有する。
  アバターを複数出すと全部が同じ動きになり、専用の `SkeletonUtils.clone` に
  差し替えない限り直らない
- パーツがそれぞれ独立した塊なら剛体で足りる。目を潰す・パーツを隠すといった
  アプリ側の処理もそのまま効く

**ボーン名はメッシュ名と必ず変える。** glTF ではボーンもメッシュも同じノード
名前空間に並ぶので、`Body` が2つあると `getObjectByName` とアニメーションの
トラック解決が壊れる。

## リグの組み方

| 症状 / 要望 | 解決策 |
|---|---|
| 親付けしたら形が崩れる | `parent` を入れただけではローカル変換が親基準に読み替えられる。**`matrix_world` を控えて、親付け後に入れ直す** |
| ビルドスクリプトを2回流すとパーツが散らばる | 作り直しで古いリグを消すとき、`parent = None` だけでは子は元の位置に戻らない（ローカル変換がボーン基準のまま残る）。ここでも `matrix_world` を入れ直す。**ポーズが乗ったまま外すとその姿勢で焼き付く**ので、先に素の姿勢へ戻す |
| 親付けの検証をレンダーでやると気付けない | 全パーツの**ワールド bbox をリグ導入前と突き合わせる**。ずれは 1e-4 以下に収まる |
| 子を付けたボーンをスケールすると、Blender とアプリで位置がずれる | Blender はボーンの **tail** に子を置き、glTF は **head** を関節にする。**ボーンを短く（0.02）して head と tail を重ねる**と、どちらでも同じ場所で潰れる（まばたき用の目のボーン） |
| 胴体に貼り付いたパーツ（翼・とさか）の支点をどこに置くか | **メッシュの原点は使えない。** モデリングで付けた原点は bbox の隅や胴体の外にあって関節にならない。**パーツと胴体表面が接している帯を数値で探し**、その端（翼なら上端）を少し胴体の中へ入れた所に head を置く。外側に置くと、動かしたとき付け根が浮いて隙間が出る |
| 接している帯を探したい | XZ に落としたシルエットを胴体と重ねて ASCII ダンプする。行ごとにパーツの内側の端と胴体の表面半径を見比べれば、どの高さで接しているかが一目で分かる |
| ボーンを動かしても胴体が上下しない | **親と `use_connect=True` でつないだボーンは `pose.location` が黙って無視される**（head が親の tail に固定されるため）。キーは普通に入るのでカーブを見ても気付けない。動かす気があるボーンはつながない |
| 平行移動が効いているか確かめたい | ポーズを見ても分からない。**メッシュの頂点のワールド座標をクリップ全体で回して振れ幅を出す**。胴体の上下 0.03 を狙ったのに 0.0038 しか出ていない、という形で分かる |
| 沈み込む／しゃがむ量の上限 | **胴体の底が床に着くまで。** 床は足の裏の高さなので、その差が使える量。超えると胴体が床と落ち影にめり込む。息で一番沈んだ所がちょうど床、が目安 |
| 座らせたいが足が邪魔 | 足が別のボーン（Root）の子なら、**沈めるのは胴体だけ**にする。足ごと下げると床にめり込む。足は別に「前へ出して床まで下げる」 |
| 足や翼を前に出したいのに胴体に隠れる | 丸い胴体に小さなパーツが付いた形では、**回すだけでは胴体の内側に留まる**。`location` で前へも動かす |
| 出したパーツが宙に浮いて、生えていないように見える | 目分量では決まらない。**胴体表面までの最短距離を測り、0 になる所まで寄せる**（測る空間を揃えるため、オブジェクトスケールを掛けるのを忘れない）。0.1 離れていると、レンダーではっきり「浮いている」と分かる |
| 「浮き」を測る道具で「めり込み」は測れない | **距離だけ見ると、接しているのと半分埋まっているのが同じ 0 に見える。** 内外の判定を必ず付ける。回転体なら**軸方向の座標 → 最大半径のプロファイルを作り、`hypot` と比べる**のが確実で速い |
| `closest_point_on_mesh` の法線で内外を判定したら符号が逆だった | **そのメッシュの法線が内向きのことがある**（レンダーは裏面も描くので見た目では気付けない）。判定を書いたら、**外にあると分かっているパーツ（くちばし・足）で必ず検算する** |
| 胴体に沿わせたいパーツが、動かすと埋まる | 「主軸を目的地へ向ける」書き方はだめ。**丸い胴体では、表面の2点を結ぶ直線は必ず中を通る**ので、剛体のパーツは半分埋まる |
| 胴体の表面をなぞって遠くまで運びたい（翼をおなかの正面へ） | **胴体が回転体なら、その軸まわりに回す。** 軸まわりの回転は各頂点の半径も高さも変えないので、**めり込み量が数値でぴったり不変**（測って 0.059 のまま動く）。パーツの向きを変える回転（付け根を支点）と、運ぶ回転（胴体の軸を支点）を分けて書き、支点の差は `location` で埋める |
| 付け根の法線まわりに回しても見た目がほとんど変わらない | **パーツの塊がその法線と同じ向きに伸びている**（翼が胴体から真横へ突き出している）と、法線まわりの回転はただの自転になる。レンダーを並べても差が読めないので、**付け根から遠い頂点の平均を「半径・接線・上下」に分解して**、パーツがどっちを向いているか数字で見る |
| 表面に沿わせて倒すと、今度は胴体に沈む | ボーンの head は胴体の**中**にある（付け根が浮かないよう、わざと入れてある）。そこを支点に倒すと塊ごと中へ入る。**半径方向へ押し出す量をもう1つのパラメータにして、めり込みの最大値を見ながら決める**。押しすぎると今度は浮くので、素の姿勢の値（0.059）を目安にする |
| 胴体の行列を控えたら軸が 12 度傾いていた | **ポーズが乗ったまま `matrix_world` を掴んでいる。** 胴体は Hips の子なので、休憩の前傾がそのまま「胴体の傾き」に見える。**素の姿勢に戻してから控える**。この軸で組み立てを誤ると、めり込み量が動くたびに変わって原因が分からなくなる |
| 後ろに倒すと床にめり込む | 倒すと底の位置も下がる。**倒す角度を先に決めてから、メッシュの最下点を測って沈み量を合わせる**。角度と沈みを同時に振ると決まらない |

## アクションの作り方

| 症状 / 要望 | 解決策 |
|---|---|
| ポーズをボーンのローカル軸で書くと符号を間違える | 「ワールドのこの軸まわりに何ラジアン」で書き、ボーン空間へ直す道具を用意する。`location` も同じ |
| Blender 5.x で `animation_data.action = act` してもキーが入らない | アクションにスロットが要る。`act.slots.new(id_type='OBJECT', ...)` を作って `animation_data.action_slot` に入れる |
| 歩きの振り幅が足りているか分からない | **足元だけを寄ったカメラで、正面と真横の2列**撮る。全身の縮小コマ送りだと足の振りも持ち上げも読めない |
| 歩きをその場の足踏みとして見せる | アプリ側でキャラを移動させないなら、**歩幅を欲張らない**。進まないのに大股だと足が滑って見える |
| 歩きに翼・とさかを足すと、歩きと無関係にひらひらして見える | **周期を足に合わせる。** 1歩ごと（＝胴体の上下と同じ、歩行周期の2倍）で動かす。別の周期にすると、同じ振り幅でも「別のものが勝手に動いている」ように見える |
| 揺れるだけのパーツ（とさか）に動きを付ける | **胴体の揺れと同じ式を位相だけ遅らせて入れる**（フォロースルー）。新しい波を作るより自然で、パラメータも遅れの量ひとつで済む |
| 振り幅がこれで足りているか分からない | アバターは小さくしか表示されない。**振り幅を3段階振って、開いた姿と閉じた姿を横に並べて**決める。翼は 0.28 rad では動いて見えず 0.42 にした |
| 立ち止まっている間に素の姿勢で固まる | 立ち止まり用のクリップ（呼吸）を1本作り、**他のクリップの重みの余りを受け持たせる**。「何も流していない状態」を無くすとアプリ側の分岐も減る |
| 座る・立ち上がるといった移り変わりをどう作るか | **クリップにしない。** 姿勢のはっきり違うループを2本用意して、アプリ側で重みを寄せる時間をゆっくりにすれば、その差がそのまま移り変わりになる |
| 左右に傾く動き（向き変え）を1本で済ませたい | **済ませない。** 傾きをアプリ側で足すと動きの出どころが2つになる。左右2本に分け、符号だけ違う引数で同じ関数から作る |

```python
# ワールド軸まわりの回転をポーズに入れる。R は bone.matrix_local の回転
R = pb.bone.matrix_local.to_3x3().normalized()
pb.rotation_quaternion = (R.transposed() @ q.to_matrix() @ R).to_quaternion()
pb.location = R.transposed() @ Vector(delta)   # 平行移動も同じ
```

## 書き出しと再生

| 症状 / 要望 | 解決策 |
|---|---|
| アクションが1本しか書き出されない | `export_animation_mode='ACTIONS'` を指定する。既定では「いま割り当てているアクション」しか出ない |
| アーマチュアが .glb から消える | 書き出しの選択（`use_selection`）に入れ忘れている。パーツがボーン親を失って散らばる |
| まばたきを歩きに重ねると、歩きが素の姿勢に引き戻される | 書き出しは**どのアクションにも全ボーンのキーを焼く**。`export_optimize_animation_size` で消す手もあるが、定数トラックごと消えてクリップの長さが変わる。**アプリ側でトラックを名前で振り分ける**方が予測できる（→ [../README.md](../README.md) 5章） |
| 書き出せたか目で確かめたい | `.glb` の JSON チャンクを読む。**ノードの親子関係・`skins`・各クリップの長さ**が分かるので、レンダーするより速くて確実 |

## 推奨ワークフロー

**形が決まってからリグを入れる。** 形を作り直すたびに親付けをやり直すことになる。

1. ボーンを置いて親付けし、**全パーツのワールド bbox をリグ導入前と突き合わせる**
2. ポーズは「ワールドのどの軸まわりに何ラジアン」で書く。**平行移動を入れたボーンは、
   狙った振れ幅がワールド座標で出ているかを数値で確かめる**（`use_connect` の罠）
3. 足元を寄って正面・真横の2列でコマ送り確認。振り幅はここで詰める
4. ビルドスクリプトを `rig_build` テキストに入れ、**実行して現物と一致することを
   確かめてから** .blend を保存（モデリング編「成果物の残し方」と同じ）
5. `.glb` に書き出し、JSON チャンクを読んでノード構成とクリップの長さを確認
6. アプリで再生して確かめる
