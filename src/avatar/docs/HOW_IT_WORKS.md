# アバターの仕組み（初心者向け）

`src/avatar/` がどう動いているかを、上から順に読めばわかるようにまとめたものです。
（開発時の決まりごとは `README.md` を見てください）

---

## 1. ひとことで言うと

**「数値 → 見た目パラメータ → 3Dの形」** という3段階の流れです。

```text
のべ達成日数 ─┐
活力(0〜100) ─┤→  look.ts  →  Look（色・表情・装備の一覧）→  Chick.tsx  → 画面
どのキャラか ─┘   （ただの計算）                              （three.jsで描く）
```

**形**は Blender で作ったモデル（`models/chick.blend` → `chick.glb`）です。
**色・表情・動き**はモデルに入っておらず、コード（`look.ts` → `Chick.tsx`）が決めます。
だから「ステージや活力で見た目がどう変わるか」を直すのに Blender は要りません。

---

## 2. 見た目を決める2つの軸

| 軸 | 何で決まる | 上下する？ | 変わるもの |
| --- | --- | --- | --- |
| **成長ステージ**（1〜6） | のべ達成日数 | 増えるだけ | 体の大きさ、つばさ・とさか・冠などの装備 |
| **活力**（0〜100） | やれば＋、サボれば− | 上下する | 色の鮮やかさ、表情、姿勢、動きの大きさ |

この2つは独立しています。だから「ステージ6なのにボロボロ」も「ステージ1で絶好調」も
ちゃんと成立します。

さらに**キャラの種類**（もりお／だいち／こむぎ）が色相（緑・青・ピンク）を決めます。

---

## 3. ファイルごとの役割

### `stage.ts` — 日数 → ステージ

`STAGES` という表があるだけです。

```text
0日 ひよこ ／ 3日 つばさ ／ 7日 大きくなる ／ 14日 とさか ／ 30日 マフラー ／ 60日 冠
```

`stageOf(days)` が「今どのステージか」を返します。

### `look.ts` — ステージ × 活力 → 見た目パラメータ（いちばん大事）

**ここが仕様書そのものです。** 色や表情を変えたいときは、まずここを触ります。
three.js には一切依存していない、ただの計算関数です。

`lookOf()` がやっていること：

- **色**：色相はキャラの種類で固定。活力が下がると**彩度を抜く**ので、
  どのキャラでも「やつれ」が同じように見える。
- **表情**：活力レベル（0〜4）で目の形を切り替える。
  `4:にっこり / 2〜3:まるい目 / 1:半目 / 0:閉じた目`
- **姿勢**：`droop`（うつむき具合）と `liveliness`（動きの大きさ）を
  活力から連続的に計算する。
- **装備**：`wings: stage >= 2` のように、ステージ番号で出す／出さないを決める。
- **おまけ**：絶好調ならキラキラ（`sparkles`）、しんどいときは汗（`sweat`）。

結果は `Look` という1つのオブジェクトにまとまって、次の `Chick.tsx` に渡ります。

> ⚠️ 色は必ず `hsl(50, 80%, 70%)` とカンマ区切りで書きます。
> スペース区切りだと three.js が読めず、**黙って真っ白になります。**

### `models/chick.blend` と `chick.glb` — 形

形の原典は `.blend`（Blender のファイル）ですが、three.js はこれを読めません。
`export_glb.py` で `.glb` に書き出したものを読んでいます。
**`.blend` を直しただけでは画面は変わりません。**書き出し直してください（手順は `README.md`）。

モデルが持っているのは**形だけ**です。色もアニメーションも入っていません。

### `Chick.tsx` — モデルを読んで、色を塗って、動かす

`Look` を受け取って、次の3つをします。

1. **読む**：`useGLTF` で `chick.glb` を読み、複製する
   （複製しないと、画面に複数出たときに全部が同じ色になる）
2. **塗る**：`Body` `Beak_Orange` `Wing_Green` …… というマテリアル名を頼りに、
   `look.ts` の色を流し込む
3. **動かす**：後述の `useFrame`

**ステージで増えるものは、モデルのパーツを出し入れして表します。**
つばさ（`Wing_L`/`Wing_R`）ととさか（`HeadFeather`）はモデルの中にあるので
`visible` を切り替えるだけ。マフラーと冠はモデルに無いので、`Chick.tsx` の中で
ドーナツと円錐を組んで乗せています。

表情は、モデルの目（球がひとつ）を**縦に潰して**作っています
（`EYE_SQUASH`。閉じた目なら 0.12 倍まで潰す）。

ステージ0のときは、ひよこではなく**卵**（`Egg`）を表示します。これは球なので
モデルを使っていません。

### `AvatarCanvas.tsx` — カメラと照明

3Dの「撮影スタジオ」です。カメラ位置と、3つのライト（全体光・右上からの主光源・
輪郭を出す逆光）を置いています。背景は透明なので、カードの色がそのまま透けます。

### `Avatar.tsx` — 入口（3Dの読み込みと、失敗の受け止め）

外から使うのはこのコンポーネントだけです。やっているのは3つ：

1. `lookOf()` を呼んで `Look` を作る
2. **WebGLが使えるか調べる** → 使えなければ空の枠を置いて、理由をコンソールに出す
3. 3Dの初期化に失敗してもアプリ全体が落ちないよう、エラー境界で受け止める

three.js とモデルはファイルサイズが大きいので、**あとから遅れて読み込む**ように
なっています（`lazy`）。その待ち時間は同じ比率の空の枠が場所を取るので、行がずれません。

アバターの見た目は 3D の一種類だけです。以前は 3D が出せない時に 2D の SVG 版へ
落としていましたが、環境によって別のアバターが出てしまうため廃止しました。

OSの「視差効果を減らす」設定がオンなら、アニメーションを止めます。

### `avatar.css`

表示サイズと、3Dが出るまでの空枠の指定です。基本さわりません。

## 4. どうやって動かしているか

**動きはすべて `Chick.tsx` の `useFrame` の中**にあります。モデルにはアニメーションの
データ（キーフレームやボーン）が入っていません。毎フレーム呼ばれる関数が、
**経過時刻 `t` から角度や大きさを計算して代入し直しているだけ**です。

動かす相手は2階建てになっています。

```text
<group root>              ← 全身にかかるもの（浮く・前かがみ・進化の跳ね）
  <group rig>             ← モデル本体の入れ物（呼吸・全体の大きさ）
    <primitive model />   ← モデルの中の翼だけ、個別に回す
    マフラー / 冠 / 汗
</group>
<Sparkles> <ContactShadows>   ← 揺れないので外に置く
```

| 動き | やっていること | 効かせる相手 |
| --- | --- | --- |
| ふわふわ浮く | `sin(t * 2.1) * 0.035` | `root.position.y` |
| 呼吸 | 横に `b` 倍、縦に `1/b` 倍（`b = 1 ± 0.03`）。体積を保つので膨らんで見える | `rig.scale` |
| 羽ばたき | `sin(t * 3.4) * 0.3` ラジアン。左右は符号を逆に | `Wing_L` / `Wing_R` |
| 前かがみ | `look.droop * 0.12` に `damp` でゆっくり寄せる | `root.rotation.x` |
| 進化の跳ね | ステージが上がった瞬間に `pop = 1`。減衰させつつ `sin` で一山だけ跳ねる | `root.scale` |
| キラキラ・汗 | 出す／出さないだけ。動きは drei 任せ | `Sparkles` / `Sweat` |
| 卵のゆらぎ | `sin(t * 1.3)` で傾けて、`abs(sin)` で跳ねる | `Egg` |

### 約束ごと3つ

**1. 揺れの大きさは全部 `amp` 倍で束ねる**

```tsx
const amp = animate ? look.liveliness : 0
```

`liveliness` は活力から作った 0〜1 の値です。やつれるとこれが小さくなり、
**どの動きも一斉に小さくなります**。OSの「視差効果を減らす」設定がオンだと
`animate` が false になり、`amp = 0` で全部ぴたりと止まります。
**新しい動きを足すときも必ず `amp` を掛けてください。**

**2. 「今の値を少し足す」のではなく「時刻 `t` から作り直す」**

`position.y += 0.01` のような書き方だと、フレーム落ちした分だけ位相がずれて
アバターごとに動きがバラバラになります。`sin(t * 2.1)` のように時刻から
計算すれば、何が起きてもずれません。

例外は**目標値に寄せたいもの**（前かがみ）です。こちらは `THREE.MathUtils.damp` を
使います。`damp` は経過時間 `delta` を見るので、fps が違っても同じ速さで寄ります。

**3. 翼の角度は上書きせず、モデルの傾きに掛ける**

翼はモデル側ですでに少し傾いています。羽ばたきでその回転を上書きしてしまうと
傾きが消えるので、初回に控えておいた姿勢（`rest`）に羽ばたきを**掛けて**います。
Blender 側で翼の角度を直しても、コードを直さずに済みます。

### ハマりどころ

呼吸で縦に `1/b` 倍すると、そのぶん**足が地面から浮きます**。
`rig.position.y` を毎フレーム押し下げて、足の裏が `y = 0` に残るようにしています。
ここを忘れると、呼吸に合わせてひよこが上下して見えます。

## 5. 「表示されるまで」を追いかけると

```text
画面が <Avatar lv={3} days={10} vitality={72} variant={0} /> を置く
  ↓
Avatar.tsx  : lookOf(10, 72, 3, 0) を呼ぶ
  ↓
stage.ts    : 10日 → ステージ3（もふもふ）
look.ts     : ステージ3 + 活力72 →
              { bodyRadius: 0.75, bodyColor: 緑, eye: 'open',
                wings: true, crest: false, ... }
  ↓
Avatar.tsx  : WebGLあり → AvatarCanvas を表示
  ↓
AvatarCanvas: カメラと照明を置いて Chick に渡す
  ↓
Chick.tsx   : chick.glb を読む → 緑を塗る → つばさを出し、とさかは隠す
              → 毎フレーム、浮かせて呼吸させて羽ばたかせる
  ↓
画面に緑のもふもふひよこが表示される
```

## 6. 変えたいとき、どこを触る？

| やりたいこと | 触るファイル |
| --- | --- |
| 色・表情・活力のしきい値を変える | `look.ts` |
| 進化に必要な日数を変える | `stage.ts` |
| **形そのもの** | `models/chick.blend`（直したら `.glb` に書き出す） |
| 動き・パーツの出し入れ | `Chick.tsx` |
| 明るさ・カメラアングル | `AvatarCanvas.tsx` |
| 表示の大きさ | `avatar.css` |
| キャラの種類を増やす | `logic.ts` の `AVATARS` と `look.ts` の `VARIANTS` の**両方**（順番を揃える） |
