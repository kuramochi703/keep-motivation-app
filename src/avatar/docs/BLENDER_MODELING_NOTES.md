## 設計図の読み取り

| 症状 / 要望 | 解決策 |
|---|---|
| 縮小表示の印象で作ると必ず形を外す | 該当パネルを拡大保存して目で測る。翼は「羽根3枚の扇」に見えて実際はミトン型1塊、頭の羽は「22度」に見えて実際は34度 |
| 輪郭・縦横比を客観視したい | Blender の Python（numpy 同梱）で画像を読み、色マスクを ASCII ダンプ。比率は設計図の数値と必ず照合 |
| 緑マスクの条件で何も取れない | パーツごとに色条件を変える。橙（くちばし）は `r > b+0.10 and r > g+0.02 and r > 0.35` |
| 羽根の境目が「隙間」か「陰影」か分からない | ASCII ダンプでシルエットが割れているか見る。多くは陰影だけで、輪郭は繋がっている |
| 明度から「谷」を検出したい | **不可**。暗い領域はライティングの陰であって谷ではない |
| ASCII ダンプから軸の角度を決めたい | **不可**。重なった塊が1つに見える。10倍拡大画像で測る |
| 比率表と完成イメージが食い違う | **絵を実測した方に従う**。比率表の「胴体60%」は絵では高さ80%・幅66%。一致するのは頭の羽16%だけだった |
| 左右のエッジを拾うと数値が暴れる | **片側だけ使う**。反対側は翼・羽・星飾りが乗る。中心 x は輪郭が綺麗な行から出して折り返す |
| シルエットの上端・下端の px が目視で決まらない | 端付近2〜3行の半幅を `h² = 2·R·d` でフィットして端と極の曲率半径を同時に出す。目視だと数 px ずれ、それが形全体を歪める |
| 小さいパーツの大きさが図ごとに違って見える | **「パーツの高さ ÷ 同じ図の胴体幅」で測る**。図の縮尺が分からなくても一致する（目はヒーロー図 0.179・比率図 0.182） |
| 比率表のパーツ寸法が絵と合わない | 胴体だけでなく**目も食い違う**（表8%・絵11%）。絵の実測を採る |
| 3/4 ビューの図から幅/高さ比を取ると値が割れる | 遠い側が潰れ近い側が膨らむ（目は 0.76 と 0.94）。**正面の図で取る**か左右平均（0.85）を使う |
| 全身図から小パーツの幅を測ると比率表より大きく出る | 全身図はカメラが水平で、足のように下に付くパーツは**高さだけが潰れて幅は潰れない**。幅/高さが 1.30（正投影の詳細図）→1.62（全身図）に化ける。**寸法は詳細図の正投影2枚から取り、全身図は「胴体下端からどれだけ出ているか」の確認だけに使う** |
| パーツの上端が図では平らに切れている | 胴体に埋まる側を切った断面。**切断線＝胴体表面**なので、その線を原点にすると取り付け高さがそのまま決まる |

```python
import bpy, numpy as np
img = bpy.data.images.load(r"C:\path\to\chick_design.png", check_existing=True)
W, H = img.size
px = np.array(img.pixels[:], dtype=np.float32).reshape(H, W, 4)[::-1, :, :3]  # 上下反転
sub = px[575:725, 955:1028]
mask = (sub[...,1] > sub[...,0]+0.05) & (sub[...,1] > sub[...,2]+0.05) & (sub[...,1] > 0.15)
ys, xs = np.nonzero(mask)
m = mask[ys.min():ys.max()+1, xs.min():xs.max()+1]
print(m.shape, m.shape[1] / m.shape[0])   # 幅/高さ比
```

## メッシュの起こし方

形によって方式を変える。手作業の球配置は非対称な有機形状では再現できない。

| 形 | 方式 |
|---|---|
| 非対称な有機形状（翼） | 距離場インフレート |
| 軸対称に近い形（くちばし・羽） | 断面リングのロフト。頂点2〜3千で十分、Decimate 不要 |
| 完全な回転体（胴体・たまご） | 実測シルエットの回転体 |
| 塊から複数の突起が出る形（足） | SDF の smooth-min ＋ 星形レイマーチ |

### 後で割れる／分かれるもの

たまごの殻のように、**閉じた1つの塊に見えていて、途中で2つに分かれる**ものは、
作ってからブーリアンで切らない。**分け目を通る格子で最初から2つ張る。**

- 格子の1行を分け目にあてる。列 `j` ごとに分け目の高さ `t_cut(j)` を出し、
  その行がちょうどそこに来るよう**列ごとに t を割り当て直す**（下の行は
  `t = t_cut * i/I`、上の行は `t = t_cut + (1-t_cut)*(i-I)/(N-I)`）。
  半径も高さも t だけの関数なので、**割り当てを変えても曲面は一切歪まない**
- こうすると2つのメッシュが分け目の頂点を共有する。**合わせ目のずれは
  数値で 0 になる**（最寄り点までの距離の最大値で確認する）。ブーリアンだと
  この 0 が出せず、閉じているはずの状態で継ぎ目が線に見える
- 分け目を「割れ目」に見せるには、**ゆるい波（2山）とギザギザの三角波（9山）を重ねる。**
  片方だけだと、きれいな波か規則的なノコギリになって割れに見えない。
  1山あたり8列は要る（72列で9山）

| 症状 / 要望 | 解決策 |
|---|---|
| 殻のように「中が空」に見せたい | Solidify を焼き込む。内側の面と切り口だけ `material_offset` / `material_offset_rim` で別マテリアルに回すと、**割れ口が濃く出て「割れた」と読める** |
| 厚みを付けたら縁（開いた辺）を探せなくなった | Solidify は塞ぐので**メッシュは閉じていて境界エッジが無い**。縁を数えたいなら、辺の使用回数ではなく**元の解析式に乗っているかで照合する** |
| 割れ口のギザギザが間引きで崩れないか心配 | ギザギザは**輪郭そのもの**なので、比率0.5でも残る。書き出した .glb を読み直してレンダーすれば分かる（→ アニメ編「書き出しと再生」） |

### 距離場インフレート

1. マスクを2倍アップサンプル → ぼかし → 0.5 で二値化（ギザギザ除去）
2. 輪郭からの**正確なユークリッド距離場**を計算（チャンファー法は方向誤差でリップルが出る）
3. `h = sqrt(1 - (1 - clamp(d/R,0,1))**2)` で円形断面に膨らませ、`blur(h, 2)` でさざ波を取る
4. 各セルに前面（`y=-h*T_F`）・背面（`y=+h*T_B`）の頂点を作り四角面を張る。`h≈0`（輪郭）では前面と背面で**同じ頂点を共有**させると自動的に閉じる
5. 前面を厚く／背面を薄く（0.62 : 0.42）すると胴体に沿う側が平らになる
6. 円形断面の丸みは `R`（`d/R` を 1 で飽和させる半径）が全て。`R = 0.78 * d.max()` でふっくら、小さくすると平たい板になる

縁の閉じ方でハマる。症状は全部「側面レンダーに数珠状の穴・筋が出る」で見分けが付かないので、
**`len(e.link_faces) < 2` のエッジ数を数えて 0 を確認する**（レンダーでは開いているか分からない）。

| 症状 | 原因・対策 |
|---|---|
| 縁に数珠状の穴が並ぶ | 距離場は細かく、メッシュは粗く取りたくて `[::2, ::2]` で間引くと、`h=0` の外周1セルのリングごと消えて前面と背面が閉じない。**間引いてから膨張させる**（`Ms = M[::S, ::S]` → `Md` を作る） |
| 縁に一本筋が入る | 4頂点とも外周リング（`h=0`）の面は厚み0のヒレになる。`if not any(Ms[a,b] ...): continue` で捨てる |
| 凹んだ所だけ縁が開く | 斜めの輪郭では四角面が張れず穴が残る。`bmesh.ops.holes_fill` で塞いでから `recalc_face_normals` |
| 縁がギザギザに波打つ | 格子の階段がそのまま出ている。`h≈0` の頂点だけを**1本の折れ線として**両隣の中点へ 0.5 で寄せる（40回）。頂点グループのスムーズだけでは取れない |

## もらったモデルを部位に割る

設計図から起こすのと違い、**分け目はこちらで決めるものではなく、モデルが既に持っている。**
探すのは分け方ではなく切れ目。

| 症状 / 要望 | 解決策 |
|---|---|
| 座標の平面で切ると境界がギザギザ・不自然な直線になる | **切らない。** 平面は稜線に乗らないので閾値をいくら詰めても直らない。モデル本来の切れ目（メッシュの連結成分・UVの継ぎ目）を探し、**島をまるごとどれか1つの部位に入れる**。閾値は「切る位置」ではなく「どの島がどの部位か」の判定に使う |
| どこに切れ目があるか分からない | 連結成分とUV島を全部列挙し、それぞれの bbox を出して棚卸しする。部位の見当はこの表だけで付く |
| UV島を部位の境に使えるか | **大きい殻は使えない**（背側／腹側の上下2枚に割れているだけで、部位の境ではない）。細かい島（くちばし・脚・指・翼の腕・目）は部位とそのまま一致する |
| 元から離れている部分（羽根など） | 連結成分でそのまま取れる |
| 左右の振り分け | 島の重心の y の符号ではなく**胴体の中心線を基準に**する。原点に揃っていないモデルが多く、中心線は 0 とは限らない。中心線基準にすると左右の枚数が揃う |
| 分け方が合っているか確かめたい | **左右パーツの頂点数・面数が一致するか見る。** 一致すれば判定は正しい |
| 部位ごとの出来を見たい | 該当部位だけ色を付け、残りを薄グレーにして正投影2面。全体を一度に色分けした1枚では、どの部位に何が入っているか読めない |
| マテリアルや頂点カラーで部位を取りたい | **不可**なことが多い。塗り分けはテクスチャ側にあり、メッシュは1マテリアル |

判定は**離れているものから順に取る。** 翼を広げたモデルは翼の先が頭より前に出ていて、
足指も前に伸びている。くちばしを x だけで先に判定すると反対側の翼端や足指を巻き込む。

### 旧FBXの取り込み

| 症状 | 解決策 |
|---|---|
| `ASCII FBX files are not supported` で読めない | インポータはバイナリ7100以降しか読まない。**6100 ASCII は入れ子のテキストなので自前で読む。** 要るのは Model ブロックの `Vertices` / `PolygonVertexIndex` / `UV` / `UVIndex` と `Lcl Translation`・`Rotation`・`Scaling` だけ |
| 配列が途中で切れる | 長い配列は折り返されている。続きの行は `,` で始まるので、そこだけ繋ぐ |
| 面の張られ方がおかしい | `PolygonVertexIndex` の負数は多角形の最終頂点の印。実インデックスは `-v-1` |
| 取り込んだら横倒し | `GlobalSettings` の `UpAxis` を見る。1（Y-up）なら X+90度で起こす |
| テクスチャが出ない | FBX に埋め込まれていないことがある。参照先は書き出した人の当時の絶対パスなので解決しない。UV は生きているので貼り直す前提にする |
| レンダリング用の背景板など要らないものが入っている | **変換の時点で名前で弾く。** 読み込んでから消すと、流し直すたびに復活する |

## 形の詰め方

### IoU で数値的に合わせる（いちばん効いた）

見た目では「太さが足りない」のか「傾きが違う」のか切り分けられない。設計図のマスクとモデルのシルエットを同じ px スケールに置いて IoU を取ると、座標降下で自動的に決まる（0.74 → 0.89）。

- モデル側のシルエットはレンダー不要。リング頂点を中心へ線形補間した点群を XZ に落とし、**パーツごとに**行ごとの左端〜右端を塗って OR する（まとめて行塗りすると隙間が埋まる）
- **両方を bbox で正規化してはいけない**。縦横比が評価されず「平たくて横に広い」形に最適化される。`S = 目標高さ / 設計図px高さ` の絶対スケールで重ねる
- 頭に埋まる部分は比較から外す（`z > Z0` で切る）。センタリングも出ている部分だけで行う
- SDF 方式なら**メッシュを作らずに IoU が回せる**。設計図 px をそのまま格子にして、奥行方向に並べた点の `sdf` の最小値が負かどうかでシルエットが出る。1回の評価が数十 ms なので座標降下が現実的（足は 0.88 → 0.95）
- 動かすパラメータは**正面図に効くものだけ**にする。奥行（y）は正面 IoU に一切効かないので、側面図の 奥行/幅 比で後から一括スケールする
- 形が距離場インフレートで決まっているパーツは IoU で形を詰める必要がない（シルエットは定義上一致する）。**IoU は取り付け（位置・回転）に回す**
- 胴体から突き出すパーツは、**胴体の外に出ている画素だけ**を評価領域にする。ただし設計図の胴体と模型の胴体は幅が違うので、**両方の胴体シルエットを領域から抜く**。抜かないと設計図の胴体のふちが「翼の欠け」として効き、いくら動かしても伸びない（0.48 → 0.57）
- 設計図の胴体シルエットは、翼に隠れている帯の上下の行から左右端を `np.interp` で内挿して作る。楕円正規化＋多項式フィット（回転体の節の方法）は**端で発散して使えなかった**
- 模型と設計図の重ね合わせは**胴体のシルエットで位置合わせする**。全体 bbox で合わせると動かしたい翼自身が基準に入ってしまう

### 位置指示への追従

「もう少し右下」のような指示は**付け根の重なり方**で来る。自動延長＋切断方式だと付け根の位置が計算結果になり狙えないので、小さいパーツは**付け根の先端を px で直接指定**し、プロファイルを対称（`EXP_B = EXP_T = 0.5`＝両端丸い楕円体）にする。2点を書き換えるだけで動かせる。

```python
topx = lambda p: (p.x/S + CX, (p.z - Z0)/S)   # world -> 設計図 px（逆変換して位置確認）
```

### 胴体へのパーツの取り付け

- 取り付け**高さ**は設計図の px 位置から逆算する。目分量で置くと顔が上すぎる（くちばしは頭頂から31%下、翼は45%下だった）
- めり込み量は**必ず数値で確認する**。レンダーでは付け根が出ているか分からない

```python
# パーツ頂点が胴体表面より外か（>0 が外）。付け根リングが全て負になる位置まで寄せる
surf = np.interp(P[:,2], z_sorted, r_sorted)      # 回転体プロファイル
out  = np.hypot(P[:,0], P[:,1]) - surf
```

- 「少し離して」は付け根が出る直前が上限。翼は +0.06 出した時点で付け根リングが +0.03 表に出た
- **胴体は原点中心とは限らない**（このモデルは z -0.526〜0.798）。設計図の「胴体の何割の高さ」を z にそのまま使うと半分ズレる。必ず `Body` の実 bbox から逆算する
- 比率表の「全体の何%」は、モデルの実際の全高（このモデルは 2.0 ではなく 1.848）と食い違う。**取り付け位置は胴体の高さ・幅を基準に測る方が安定する**
- 胴体の底は平らに近いので、**底に付くパーツは「一番低い所」ではなく「足跡の一番外側で胴体表面が一番高い所」で沈み量を決める**。内側に合わせると外側に隙間が空く（足で 0.066）

- 回転体の表面に貼るパーツの局所フレームは法線 `n ∝ (cosθ, sinθ, -r'(z))` から作る。縦軸は `v = normalize(Z - (Z·n)n)`、横軸は `u = v × n`
- 球状パーツを「輪郭まで丸く見せる」には赤道が胴体表面のわずか内側に来るまで沈める。沈め量の目安は `(パーツ半幅)² / (2·胴体半径)`
- **既存オブジェクトにはオブジェクトスケールが残っていることがある**（胴体は 0.83）。解析プロファイル（＝ビルド時のローカル座標）で出した位置をそのままワールドとして使うとパーツが宙に浮く。`obj.dimensions` とメッシュ実寸を比べれば一発で分かる。位置は必ず `Body.matrix_world` を通す
- めり込みチェックは**同じ空間で測る**。`body_radius(z)` はローカルなので、ワールドで測るなら `S*body_radius(z/S)` に直す。ヒストグラムのビンで表面半径を作ると空ビンが 0 になり、浮いていないのに「全部外」と出る

### 確認レンダー

- **正面・側面・3/4 の3枚**撮る。平たさ／尖りは側面、太さは正面でしか分からない。3/4 だけだと「平たい小石」に気づけない
- 浮き・接地は**パーツだけを画面いっぱいにしたアップ**で見る。全身の縮小レンダーを並べても分からない。落ち影がパーツから離れて出ていたら浮いている
- 前後まわりこみ（0〜180度）も撮る。**かすめる角度（60〜120度）で輪郭から外れて見えるか**が接地の最終確認になる
- 形を見せるときは**対象パーツだけ表示**する（仮の頭などは `hide_render = True`）。判断の邪魔になる
- 案出しはパラメータを3段階振って numpy で横に連結し、デスクトップにコピーする。文章では詰まらない

## 左右対称パーツ

`scale.x = -1` は法線が反転し Euler も読みにくくなる。**メッシュのローカル X 反転＋回転の Y/Z 成分反転**が綺麗。

```python
me = left.data.copy()
for v in me.vertices: v.co.x = -v.co.x
right.data = me
right.location = Vector((-lx, ly, lz))
right.rotation_euler = Euler((rx, -ry, -rz), 'XYZ')
# 編集モードで normals_make_consistent(inside=False) を忘れない
```

- 原点は**付け根（胴体に接する側）**：3Dカーソル移動 → `origin_set(type='ORIGIN_CURSOR')`
- 命名はキャラ基準（正面が -Y なら、キャラの左＝ワールド +X が `Wing_L`）

## 比率

設計図の比率（全体高さ=100%）をそのまま寸法に落とし、作り終わったら正規化する。

```python
TOTAL_H = 2.0
d = obj.dimensions
obj.scale = (0.18*TOTAL_H/d.x, 0.075*TOTAL_H/d.y, 0.22*TOTAL_H/d.z)
bpy.ops.object.transform_apply(location=False, rotation=False, scale=True)
```

頭の羽 16% / 胴体 60% / 目 8% / くちばし 6% / 翼 22% / 足 8%

足は比率表の 8%（高さ）が絵と一致する。幅は詳細図の 幅/高さ = 1.30、奥行は 奥行/幅 = 0.73。

翼も詳細図の 幅/高さ = 0.77 が比率表の 18/22 = 0.82 とほぼ一致する。奥行は側面詳細図の 奥行/幅 = 0.66。
詳細図の翼は**取り付け後の姿勢のまま**描かれている（主軸が鉛直から 19 度）ので、形にさらに傾きを足すと倒れすぎる。
足りないのは**ヨー（翼の先を前へ振る）で、IoU で -19 度**になった。

ただし**胴体だけは比率表と完成イメージが食い違う**。絵の実測は高さ 80% / 幅 66%（比率表は60%）で、絵の方に合わせないと他のパーツが全部埋まる。頭の羽16%・足8%は絵と一致するので、上端＝羽の先端・下端＝足の裏で全高2.0に収まる。

## 光の焼き込み（動かない背景）

背景の部屋のように動かない物は、Cycles で照らした結果をテクスチャに焼いて、three.js では
照明を当てずに貼る（`MeshBasicMaterial`）。リアルタイムの照明より明るく柔らかく出て、ブラウザも軽い。

| 症状 / 要望 | 解決策 |
|---|---|
| 細長い物（幅40・高さ0.28の幅木）の焼き込みが真っ黒 | `smart_project` は縦横比を保つので、テクスチャの端の数画素に押し込まれる。**平らで単純な物は UV を座標から直接書いて引き伸ばす**。光は緩やかにしか変わらないので伸ばしても崩れない |
| 見えない面（壁に付く裏・底）で焼き込みが潰れる | 開いた UV が見える面と重なっている。見えない面は帯の外の1点へ逃がす |
| 壁の中央が白く飛んで色が消える | 手前の面光源が強すぎる。空の光を主にして面光源は控えめに。明るさは焼いたあと一律に掛けて揃える |
| 明るさを揃えたいが中央値が 0 になる | UV の島の外は焼かれず黒のまま。**焼けた画素だけで測る** |
| 交差した部品（十字の桟）の交点に黒い点 | 隠れた部分の暗さが縁ににじむ。**部品を貫通させず、当たる所で分けて作る** |
| 動かす物（狭い画面で寄せる本や鉢）の影が取り残される | 床に焼かない（焼くときは隠す）。足元に影の板を敷き、持ち主以外を隠して AO を焼き、`1 - AO` を透明度にして子にする |
| 影の板の縁に黒い点線 | 板の UV に余白があると、焼かれない黒が「濃い影」としてにじむ。`create_grid(calc_uvs=True)` で板全体をテクスチャいっぱいにする（先に `bm.loops.layers.uv.new()` が要る） |
| 影の板が遠くへ飛ぶ／足元に来ない | `bound_box` は持ち主のローカル座標。そのまま子にすればよく、`matrix_parent_inverse` を足すと二重にずれる |
| three.js で窓ガラスだけ消える | 材質を差し替えるとき `side` を引き継ぐ。glTF は両面だが、差し替えた材質の既定は片面で、奥を向いた面が消える |

## Blender MCP / 環境のハマりどころ

### 作業ループの組み立て方

パーツ1個は「**設計図を読む → 形を作る → 撮って見る**」を何十周もする。1周が遅いと形が詰まらないので、
この3つが全部 `execute_blender_code` の中で完結するように組む。Blender の UI は一度も触らない。

| 症状 / 要望 | 解決策 |
|---|---|
| 前の呼び出しで定義した関数が `NameError` になる | `execute_blender_code` の名前空間は**毎回リセットされる**。使い回す関数・重い中間データは `bpy.app.driver_namespace` に入れる（`bpy.app.driver_namespace['build'] = build` → 次の呼び出しで取り出す） |
| WSL 側で画像を解析しようとすると `ModuleNotFoundError` | WSL の素の python3 には numpy も PIL も無い。**画像解析は全部 Blender の Python でやる**（numpy 同梱）。設計図は一度 `.npy` に落として Temp に置けば、以後の呼び出しで読み直すだけで済む |
| 設計図を Blender に読ませたい | Blender が Windows 側なら WSL のファイルを **UNC パスで直接開ける**：`r'\\wsl.localhost\<Distro>\home\...\chick_design.png'`。コピー不要（MCP の `get_blendfile_summary_path_info` が返す `filepath` を見れば、Blender から WSL がどう見えているか分かる） |
| 作った画像・レンダーを Claude 側から見たい | `C:\Users\<user>\AppData\Local\Temp\blender_mcp_in\` に保存し、WSL からは `/mnt/c/...` で読む。UNC 越しに WSL へ直接書くより速く、MCP の出力先とも一致する |
| 設計図の一部を「目で」見たい | `np.repeat` で整数倍に拡大 → `bpy.data.images.new` + `pixels.foreach_set` + `save()` で PNG 化。ぼけないので px が数えられる |
| 確認レンダーのアングル・大きさが毎回変わって比較できない | `render_viewport_to_path` ではなく、**使い捨ての ORTHO カメラを作って撮る**。対象の bbox から `ortho_scale` を決めれば全カット同一スケールになる。撮り終わったらカメラを削除する（残すと `ChkCam` がシーンに紛れ込む） |
| WSL に `blender` コマンドが無い | Windows の `blender.exe` を叩けばよい（`-b <file> -P <script>`）。**スクリプトも .blend も相対パスで渡す。** 絶対パスだと `\\wsl.localhost\...` の後ろに二重連結されて開けない |
| 解析用に読んだ画像で .blend が肥大する | `bpy.data.images` は .blend に埋め込まれる。保存前に `Render Result` 以外を消す（今回 7 枚で数 MB） |

```python
# 使い捨て ORTHO カメラ。az=0 は +Y から見る＝キャラの背面（正面が -Y なら az=180 が正面）
d = Vector((sin(az)*cos(el), cos(az)*cos(el), sin(el)))
cam.location = Vector(center) + d*(rad*6)
cam.rotation_euler = d.to_track_quat('Z','Y').to_euler()
```

### API の地雷

- `render_viewport_to_path` は**シーン全体**をレンダーする。デフォルトの Cube がカメラを覆って真っ白／真っ灰色になるので `Cube.hide_render = True`
- Blender 5.2 では `mesh.use_auto_smooth` が**廃止**（`AttributeError`）。`shade_smooth()` のみ。
  角度で分けたいなら `bpy.ops.object.shade_auto_smooth(angle=...)`（モディファイアが付く。
  書き出しの `export_apply=True` で焼ける）
- Blender 5.2 の `scene.render.engine` の enum は `BLENDER_EEVEE` / `BLENDER_WORKBENCH` / `CYCLES`。**`BLENDER_EEVEE_NEXT` は無い**
- 同梱 numpy は 2.x。`arr.ptp()` は**削除済み**（`np.ptp(arr)` を使う）。`arr.min()` 等はそのまま
- `hasattr(...) if ... else ...` の三項演算子は左辺評価で例外になる。素直に `if` で書く
- transform を変えた直後の `matrix_world` は**古い値**。`bpy.context.view_layer.update()` を挟む
- `transform_apply` / `modifier_apply` は `view_layer.objects.active` を入れただけでは**無言で何もしない**。`select_all(action='DESELECT')` → `obj.select_set(True)` も要る。気付かずにオブジェクトスケールが残る
- `film_transparent = True` だけではアルファが出ない。`render.image_settings.color_mode = 'RGBA'` を併せて入れる（さもないとシルエットの bbox が画面全体になる）
- `bpy.types.RenderEngine.__subclasses__()` には `bl_idname` を持たないクラスがある（`HydraRenderEngine`）
- 形状確認は「フラットな正面」より **3/4 ビュー＋エリアライト**の方が凹凸が分かる

### 成果物の残し方

- **パーツが少ないモデルは、.blend ごと1本のスクリプトで作り直せる**（`egg/build.py`）。
  こうすると「.blend の中の手作業」が原理的に存在しなくなり、現物との突き合わせも要らない。
  スクリプトはリポジトリに置き、**同じものを `bpy.data.texts` にも入れておく**
- パーツの再生成スクリプトは `bpy.data.texts` に `<part>_build` という名前で入れる（`body_build` / `eye_build` / `foot_build`）。
  .blend と一緒に版管理されるので、形を直すときは座標をいじるのではなくスクリプトを直して作り直す
- 保存する前に**そのスクリプトを実際に実行し、現物と頂点座標が一致するか**を確かめる（差が 1e-4 以下なら同一）。
  手でいじった調整がスクリプトに反映されていないと、次に再生成した瞬間に形が変わる
- 設計図から起こしたマスクを Temp の `.npy` で参照したままにすると、.blend だけでは再生成できない。
  **マスクはスクリプトに埋め込む**：`np.packbits` → `zlib` → `base64` で 88x68 が約 1KB

```python
blob = base64.b64encode(zlib.compress(np.packbits(M).tobytes(), 9)).decode()
M = np.unpackbits(np.frombuffer(zlib.decompress(base64.b64decode(blob)), np.uint8)
    )[:H*W].reshape(H, W).astype(bool)
```

## 推奨ワークフロー

**この順序であることに意味がある。**「目で決めること」と「数値で決めること」を混ぜると詰まる。
方式（軸の向き・パーツ構成）は目でしか決まらず、寸法は目では決まらない。1〜4 が前者、5 以降が後者。

1. 該当パネルを拡大保存して形を**目で**確認（角度も px で測る）
2. 色マスクを作り、縦横比を設計図の数値と照合
3. 切れ込みがシルエットを割っているか陰影だけかを ASCII ダンプで判定
4. **方式を決める**：回転体なら実測シルエット、軸対称ならロフト、非対称な有機形状なら距離場インフレート、
   塊から突起が出る形なら SDF の smooth-min。ここで**パーツの軸の向きまで絵から決め切る**（後で IoU に入ると直せない）
5. IoU で数値的に詰める → 縁だけ重点スムーズ → 比率に正規化 → `shade_smooth()`
6. 左右対称パーツはローカル X 反転で鏡像
7. 正面・側面・3/4 の3枚でレンダー確認
8. 胴体に載せるときは付け根のめり込みを数値で確認してから位置を決める
9. ビルドスクリプトを `<part>_build` テキストに入れ、**実行して現物と一致することを確かめてから** .blend を保存

動かすのはここまで終わってから。形を作り直すたびに親付けをやり直すことになるので、
リグは最後に入れる（→ [BLENDER_ANIMATION_NOTES.md](BLENDER_ANIMATION_NOTES.md)）。
