# アバター（3Dのひよこ）

このフォルダだけで完結する説明書。アプリ全体は [README.md](../../README.md)、
構成図は [ARCHITECTURE.md](../../ARCHITECTURE.md)。

```text
ステージ(0〜3) ─┐
気分(6段階)    ─┤→  look.ts  →  Look（色・表情・装備）→  Chick.tsx  → 画面
色相(0〜359)   ─┘   （ただの計算）                        （three.js で描く）
```

- **形と動き** = Blender のモデル（`models/chick.blend` → `chick.glb`）
- **色・表情・装備の出し入れ** = コード。Blender を開かずに変えられる
- **姿勢の動き** = 全部モデルの中のクリップ。コードは「どれを流すか」と
  「歩いてどこへ行くか」だけ
- VRM は不採用。人型前提の規格でひよこに合わず、専用ランタイムが増えるだけ

## 見た目を決める3つの入力

| 入力 | レンジ | 効くもの |
| --- | --- | --- |
| 色相（`hue`） | 0〜359（ユーザーが選ぶ） | 色相だけ。**気分では動かさない** |
| ステージ | 0〜3（**下がらない**） | 体格・装備 |
| 気分 | 6段階（連続サイクル／放置サイクルから計算） | 彩度・明度・表情・姿勢 |

- ステージと気分は独立。「究極体なのにぐったり」「幼体でかがやき」も成立
- 原典はコード。ステージは `stage.ts` の `STAGES`、気分は `state/logic.ts` の `MOODS`。
  `look.ts` は**その2つを引いて描画用の値に直すだけ**
- **色を足すときは `logic.ts` の `HUES` に数字を1つ足すだけ。**
  アバターの種類（`AVATARS` と `VARIANTS` を同じ並び順に保つ決まりごと）は無くなった

### 気分でどう変わるか

`MOODS`（`state/logic.ts`）の表をそのまま引く。**落ち込みは彩度で表し、明度は 58 より下げない。**

| 気分 | 条件 | 彩度 / 明度 | 目 | ほか |
| --- | --- | --- | --- | --- |
| ぐったり | 3サイクル放置 | 8 / 58 | 閉じる | **歩かず座り込む**・あぶら汗 |
| うつむき | 2サイクル放置 | 18 / 58 | 半目 | あんまり動かない（`liveliness` 0.2） |
| すこし元気 | 連続1サイクル | 34 / 66 | まるい目 | — |
| 元気 | 連続2サイクル | 44 / 72 | まるい目 | — |
| いきいき | 連続3〜6サイクル | 56 / 80 | にっこり ∩ | — |
| かがやき | 連続7サイクル以上 | 56 / 80 | にっこり ∩ | **光の粒が舞う**（`Sparkles`） |

- 前かがみ（`droop`）は `liveliness` から出す。0.6 以上でまっすぐ
- **座り込む閾値は `liveliness > 0.15`**（`Chick.tsx` の `pick()`）。うつむき（0.2）は座らない
- おなか・くちばし・翼の色は、からだの色から機械的に作る（`look.ts` / `Chick.tsx` の `accent`）

### ステージでどう変わるか

| ステージ | 到達条件 | 増えるもの | 実体 |
| --- | --- | --- | --- |
| 0 たまご | 初期状態 | 殻だけ。**気分を持たず、色相以外は固定**（彩度24 / 明度88） | `egg.glb`（`Egg`）。揺れる・割れるクリップつき |
| 1 幼体 | 2サイクル連続 | からだ・あし・くちばし・小さいとさか | 常に表示 |
| 2 成体 | 直近5サイクルで4サイクル | つばさ ＋ 一回り大きく ＋ とさかが立派に | `Wing_L` / `Wing_R`、`bodyRadius`、`crestScale` |
| 3 究極体 | 14サイクル連続 | マフラー ＋ 冠 | `Chick.tsx` の `Scarf` / `Crown`（モデルには無い） |

- **たまごはダッシュボードに出る。** 最初の2サイクルを積むまでが殻の中
- 孵化と進化の演出は `MainPage.tsx` が流し、`avatars.seen_stage` で**1回だけ**に絞る
- **とさかはどのステージでも消さない。** 消すとひよこに見えない。成長は大きさで表現
- 目は球ひとつ。`EYE_SQUASH` の倍率で**縦に潰して**表情を作る。形そのものを変えるなら
  Blender でシェイプキーを持たせてモーフへ
- 表情はメッシュの `scale`、まばたき・目つぶりはボーンの `scale`。掛け合わさるので
  半目のままでもまばたきする
- ほっぺの赤みはモデルに無く、未使用。`headRatio` も現状どこからも参照していない

### 色の決め方

- **元気ほど明るく、彩度は上げすぎない**（パステル）。上限は彩度 56 / 明度 80。
  落ち込みは彩度を抜いて表し、明度は 58 より下げない（暗く沈めると汚く見える）
- やつれ＝彩度が抜けて暗くなる。どの種類でも同じ読み取りになる
- **指定した色がそのまま出るとは限らない。** 照明とセットで決まるので、
  `AvatarCanvas.tsx` に2つの仕掛けあり
  - **トーンマッピングを切ってある**（`flat`）。既定の ACES は明るい色ほど灰色へ寄せる
  - **光の強さが 1 ではなく 2 前後。** three.js の拡散反射は明るさを π で割るため、
    強さ1では指定した色の 1/3 ほどにしかならない
- 「思ったより暗い・くすむ」ときは `look.ts` の数字より先にここを疑うこと

## 形を直したとき（Blender → アプリ）

`chick.blend` を直しただけでは**アプリの見た目は変わらない。**書き出し直すこと。

```sh
B="/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe"

# ひよこ
"$B" -b src/avatar/models/chick.blend -P src/avatar/models/export_glb.py

# たまご。**形を直すのは egg.blend ではなく egg_build.py。**
# 流すと egg.blend ごと作り直されるので、.blend の中の手作業は残らない
"$B" -b --factory-startup -P src/avatar/models/egg_build.py
"$B" -b src/avatar/models/egg.blend -P src/avatar/models/export_egg_glb.py
```

- .blend は読むだけで保存しない
- やっていること3つ：**間引き**（約 4MB → 約 0.7MB）、**塗り分けマスクを頂点カラーで運ぶ**
  （glTF はノードの Mix を運べない）、カメラ・ライトを落とす
- パーツを足したら `export_glb.py` の `RATIOS` にも追加。**載っていないものは消える**
- アーマチュア `Rig` だけは `RATIOS` の外。間引き対象外だが書き出しの選択には要る

## どうやって動かしているか

```text
chick.glb のクリップ  Idle / Walk / TurnL / TurnR / Rest / Jump / Blink
        │  AnimationMixer が再生
        └─ ボーン9本（Root / Hips / LegL / LegR / EyeL / EyeR / WingL / WingR / Crest）

Chick.tsx  pick() … 次にどれを流すか
           roam() … 歩いている間の立ち位置と向き
```

### 原理（three.js は何をしているか）

コードに `sin(t)` は1つも無い。動きの正体は
**「名前付きのトラックを、重みを付けて足し合わせたもの」**。

```text
AnimationClip「Walk」          … トラックの束＋長さ（1.0秒）
  ├ KeyframeTrack "Hips.quaternion"  … 時刻の並びと値の並び
  ├ KeyframeTrack "Hips.position"
  └ …（ボーンごと・プロパティごとに1本）
        ↓
AnimationMixer（root = rig の <group>）
  トラック名 "Hips" で root 以下のノードを引き当て、キーを補間して
  .position / .quaternion / .scale へ**書き込む**
        ↓
AnimationAction … クリップ1本の再生状態（時刻・ループ・重み）
```

- **トラックはノード名で当たる。** Blender でボーン名を変えると、そのトラックは
  黙って当たらなくなる（エラー無し）
- **書き込むのはボーンの位置・回転・スケールだけ。** メッシュは付いてくるだけなので、
  コード側の処理（目を潰す・翼を隠す・とさかを拡大）と衝突しない
- **同じプロパティを複数のアクションが書くと重み付き平均。** mixer が書き込みを溜めて
  重みの合計で割る。**重みの合計を1にするのはこのため**
- **時間を進めるのは `mixer.update(delta)`。** `useAnimations`（drei）任せ。
  `mixer.timeScale = 0` でクリップの時間だけ止まる
- React の関わりは薄い。`useAnimations(clips, rig)` が mixer と `actions` を作るだけで、
  毎フレームの `useFrame` は再描画を起こさない。だから立ち位置や重みは `useRef`

### モデルが持っているクリップ

| クリップ | 長さ | 中身 | 流し方 |
| --- | --- | --- | --- |
| `Idle` | 2.5秒 | 立ち止まり。ゆっくり呼吸、翼ととさかがわずかに揺れる | ループ。**他が0のとき余りを受け持つ** |
| `Walk` | 1.0秒（2歩） | 足を交互に運び、胴体が上下＋よちよち左右に揺れる。1歩ごとに翼を開き、とさかが遅れて振れる | ループ。重みで出し入れ |
| `TurnL` / `TurnR` | 0.67秒 | その場の向き変え。小刻みな足踏み＋回る側へ傾ける | ループ。重みで出し入れ |
| `Rest` | 3.0秒 | 休憩。お尻で座り、足を前へ・翼をおなかへ、**目を閉じて**深い呼吸 | ループ。重みをゆっくり寄せる |
| `Jump` | 1.25秒 | しゃがむ→翼を開いて跳ぶ→足をたたむ→着地で潰れる | 1回きり（`LoopOnce`） |
| `Blink` | 4.0秒 | 4秒に1回、目のボーンを縦に潰す | ループで流しっぱなし |

たまご（`egg.glb`。ステージ0でだけ読む別のモデル）。

| クリップ | 長さ | 中身 | 流し方 |
| --- | --- | --- | --- |
| `EggIdle` | 2.5秒 | 左右にゆっくり揺れる（5度） | ループ。既定 |
| `EggCrack` | 3.0秒 | 中から3回突かれてひびが入り、上半分が飛んで横に転がる | 1回きり（`LoopOnce`）。`hatching` が true になった瞬間 |

- 殻は `Shell_Bottom` / `Shell_Top` の2つ。**割れ線で分かれているが頂点は完全に一致する**ので、
  閉じている間は継ぎ目が開かない（うっすら出るひびの線は、殻がそこで割れる印としてそのまま使っている）
- 割れ終わりは `clampWhenFinished` で最後の姿のまま止まる。**もう一度見せるにはアバターを作り直す**
  （デバッグ画面の「戻す」は `key` を変えている）

- 翼ととさかは**歩き・跳びと同じ周期**。別周期にすると歩きと無関係にひらひら見える
- **向き変えが左右2本なのは傾ける向きが逆だから。** 傾きをコードで足すと
  動きの出どころが2つになる
- **座り込む・立ち上がるはモデルに無い。** `Idle` と `Rest` の姿勢差が、重みを寄せる間に
  そのまま動きになる。目も同じで、`Rest` は閉じた目を持っているだけ
- パーツは**スキニングせず**ボーンに親付けした剛体。コードから見ればただのメッシュのまま

### どれを流すか（`pick()`）

```text
idle ──向きがずれている──> turn ──向き直り終わり──> idle
  │                          ↑
  ├──行き先を決めて──────────┘  └──向き直り終わり──> walk ──> idle
  ├──> jump ──> idle
  └──> rest ──> idle
```

- **向きが 0.5 ラジアン以上ずれたら必ず `turn` を挟む。** 立ったまま回すと足が滑って見える
- 気分が落ちている（`liveliness <= 0.15`）と歩き出さず座り込む
- `animate` が false（OSの「視差効果を減らす」）なら `mixer.timeScale = 0` にしたうえで
  **状態機械ごと停止。** 重みを寄せ続けると、時間が止まっていても姿勢が動く

### 重みの配り方

- 姿勢のクリップは**全部流しっぱなし。合計1**になるよう重みを配る
- `Walk` / `TurnL` / `TurnR` / `Rest` / `Jump` のうち今のモードだけを1へ寄せ、
  **余りは `Idle`。** 「何も流していない素の姿勢」で固まることがない
- 寄せる速さはクリップごと（`RATE`）。休憩は遅く（座り込む間合い）、ジャンプは速く

目は姿勢と別枠。

```text
姿勢  Walk / TurnL / TurnR / Rest / Jump ─ 余りは Idle   合計 1
目    Blink（1 − Rest の重み） ＋ Rest（閉じた目）        合計 1
```

- 目を書くクリップは `Blink` と `Rest` の2本だけ（`EYE_CLIPS`）。歩きながらまばたきさせる
  ため、姿勢の取り合いには入れない
- **`Rest` の重みぶんだけ `Blink` を下げる。** 両方を重み1で流すと、開いた目（1.0）と
  閉じた目（0.08）が平均されて半目のまま止まる

### どこへ歩くか（`roam()`）

Walk クリップ自体はその場の足踏み。歩き回らせているのは `roam()`。

- 範囲は `ROAM_X` / `ROAM_Z`。端まで来たら中心へ向き直して戻る。
  **カメラや `avatar.css` の比率を変えたら測り直すこと**
- 奥行きは遠近で大きさが変わるので左右より狭い
- 立ち止まると正面（カメラ向き）に向き直る
- 進む量は Walk の重みに比例。そうしないと歩き出しと止まりぎわに足が滑る
- 進む方向は `heading`（行きたい方向）ではなく `facing`（いま向いている方向）。
  振り向く途中の横滑り防止
- 移動だけは Blender に置けない（毎回同じ道順になり、範囲も決められない）。
  **姿勢はクリップ、道順はコード**

### 動かないもの

look.ts が決める**状態**。時間で変化させない。

| もの | やっていること |
| --- | --- |
| 前かがみ | `look.droop * 0.12` を外側 `group` の `rotation.x` へ |
| 目つき | `EYE_SQUASH` の倍率で目を縦に潰す |
| 体格 | `look.bodyRadius * SIZE` を `rig` の `scale` へ |
| たまご | ステージ0では殻だけ。姿勢を作るのはクリップで、ここは `hatching` を渡すだけ |

### 約束ごと

1. **新しい動きはコードではなく Blender に足す。** `sin(t)` で角度を作らない
   （例外は `roam()` だけ）。動きの出どころが2つになると追えなくなる。
   足すならアクションを1本増やし、`pick()` の条件と `POSTURE` への登録だけ書く
2. **クリップは `play()` しっぱなしにして重みで出し入れ。** 毎回 `play()` / `stop()` だと
   歩き出しと止まりが瞬間的になる。ジャンプだけ例外で `reset().play()` し、
   **終わったら必ず `stop()`**（放置すると最後の姿勢を重み1で押さえ続ける）

### ハマりどころ

- Blender の書き出しは**どのアクションにも全ボーンのキーを焼く**。そのままだと
  `Blink` の脚や胴（素の姿勢）が歩きを引き戻す。`Chick.tsx` でトラックを名前で振り分け、
  目は `EYE_CLIPS` だけに、`Blink` からは姿勢を落としている
- ボーンを足す・目を動かすクリップを増やすときは、この振り分け（`clips` の `useMemo`）と
  `EYE_CLIPS` を見直すこと
- Blender 側で詰まったら [docs/BLENDER_ANIMATION_NOTES.md](docs/BLENDER_ANIMATION_NOTES.md)

## いじる時の決まりごと

1. **モデルの中の座標は実測した定数を使う。** `FOOT_Y` / `HEAD_TOP` / `BODY_R` は
   chick.glb の実測値。マフラーや冠はこれを基準に置く。**形を大きく変えたら測り直す**
2. **マテリアルはパーツ名で引いている**（`Body` / `Beak_Orange` / `Wing_Green` …）。
   Blender で改名すると**黙って色が付かなくなる**
3. **色はカンマ区切りの `hsl()` で書く。** `hsl(50 80% 70%)` は three.js が解釈できず
   **黙って白になる。** `look.ts` の `hsl()` ヘルパーを通すのが安全
4. **パーツはボーンに親付け。スキニングしない。** スキンドメッシュにすると
   `scene.clone(true)` がボーンを共有し、**全アバターが同じ動きになる**
   （`SkeletonUtils.clone` が要る）。剛体なら目を潰す・翼を回す・パーツを隠すがそのまま効く
5. **ボーン名はメッシュ名と必ず変える。** glTF では同じ名前空間に並ぶので、
   `Body` ボーンと `Body` メッシュがあると `getObjectByName` とトラック解決が壊れる

## 3D が使えない環境

- WebGL 無し・初期化失敗のときは、同じ比率の空枠（`.avatar-placeholder`）だけが残る
- アプリは止まらない。コンソールに `[avatar]` で始まる警告が出る
- three.js とモデルは遅延読み込み。読み込み中も同じ枠

## なぜこの方式なのか（決定の記録・2026-09-06）

描きたいもの（ステージごとに何が増えるか）を先に決めてから方式を選んだ。

| 方式 | 欠点（不採用の理由） |
| --- | --- |
| インライン SVG（採用前） | 複雑な絵は手書きが大変 |
| 画像ファイル | ステージ×気分の枚数ぶん要る（最大24枚） |
| SVG ファイル読込 | パーツ制御が書き出し方しだい |
| Lottie / Rive 等 | **GUI ツールのファイル待ち。描ける人が居ないと1枚も出せない** |
| **3D（react-three-fiber）** ← 採用 | 容量（three.js gzip 250KB ＋ モデル 0.7MB。別チャンクで遅延読み込み） |

- 絵を描ける人を待たなくていい／「増えるもの」を足すだけでステージが作れる／
  2軸の掛け合わせが自然に出る、の3点で採用

> **その後**（2026-09-20）: 形を Blender のモデルへ差し替え。色・表情はコードのまま。
> 動きも全部 Blender のクリップへ寄せ、コード側の揺らぎ（浮遊・呼吸・羽ばたき・
> 進化の跳ね）と光の粒（`Sparkles`）は削除。**動きの出どころは1つ**という決め。
