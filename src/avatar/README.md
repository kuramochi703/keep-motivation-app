# アバター（3Dのひよこ）

このフォルダだけで完結する説明書です。**上から読めば仕組みが分かり、
下の方に「触る時の決まりごと」があります。**

アプリ全体の話は [README.md](../../README.md)、構成図は
[ARCHITECTURE.md](../../ARCHITECTURE.md) を参照。

---

## 1. ひとことで言うと

**「数値 → 見た目パラメータ → 3Dの形」** という3段階の流れです。

```text
のべ達成日数 ─┐
活力(0〜100) ─┤→  look.ts  →  Look（色・表情・装備の一覧）→  Chick.tsx  → 画面
どのキャラか ─┘   （ただの計算）                              （three.jsで描く）
```

**形と動き**は Blender で作ったモデル（`models/chick.blend` → `chick.glb`）です。
**色・表情**はモデルに入っておらず、コードが決めます。
だから「ステージや活力で見た目がどう変わるか」を直すのに Blender は要りません。
逆に**姿勢の動きは全部モデルの中**にあり、コードは「どれを流すか」と
「歩いてどこへ行くか」しか決めません（→ [5](#5-どうやって動かしているか)）。

VRM は使いません。あれは人型（ボーン・表情の規格）前提でひよこには合わず、
専用ランタイム（`@pixiv/three-vrm`）が増えるだけになるためです。

## 3. 見た目を決める軸

```text
種類  もりお / だいち / こむぎ  ← 目標設定でユーザーが選ぶ。色相が変わる
軸1  成長ステージ 1〜6         ← のべ達成日数で体格・装備が変わる。下がらない
軸2  活力 0〜100              ← やれば＋、サボれば−。彩度・表情・姿勢が変わる
```

2軸は独立しています。「ステージ6でボロボロ」も「ステージ1で絶好調」も成立するので、
片方を変えてももう片方は壊れません。

**一覧はコード側が原典です。** ステージの名前・到達日数は `stage.ts` の `STAGES`、
活力のしきい値と表情・装備の条件は `look.ts` の `lookOf`（レベルは `state/logic.ts` の `levelOf`）。
種類を増やすときは、`logic.ts` の `AVATARS`（名前）と `look.ts` の `VARIANTS`（色相）の
**両方に、同じ並び順で**足してください。並び順が id です。

### ステージとモデルの対応

ステージで増えるものは、モデルのパーツを出し入れして表しています（`Chick.tsx`）。

| ステージ | 見た目 | 実体 |
| --- | --- | --- |
| 1 | からだ・あし・くちばし・とさか | 常に出ている |
| 2 | つばさ | `Wing_L` / `Wing_R` を表示 |
| 3 | 一回り大きくなる | `look.bodyRadius` |
| 4 | とさかが立派になる | `look.crestScale`（`HeadFeather` の倍率） |
| 5 | マフラー | `Chick.tsx` の `Scarf`（モデルには無い） |
| 6 | 冠 | `Chick.tsx` の `Crown`（モデルには無い） |

表情（`look.eye`）は、モデルの目（球ひとつ）を**縦に潰して**出しています（`EYE_SQUASH`）。
こちらはメッシュの `scale`、まばたきと休憩の目つぶりはボーンの `scale` なので、
掛け合わさります（しょんぼりした半目のまま、まばたきもできます）。
本当に形を変えたければ Blender でシェイプキーを持たせて、潰す代わりにモーフを動かしてください。
ほっぺの赤みはモデルに無いので、いまは出していません。

**とさか（`HeadFeather`）はどのステージでも消しません。** 消すとひよこに見えず、
別の生き物になってしまうためです。成長は出し入れではなく大きさで表しています。

ステージ0（たまご）はトップページ専用です。モデルではなく球で描いています（`Egg`）。

### 色の決め方

**元気なときほど明るく、彩度は上げすぎない**（パステル）。彩度で元気さを出すと
絵の具のような色になって可愛くなくなるので、元気さは主に明度で出しています。
やつれると彩度が抜けて暗くなる、が「やつれ」の合図です（`look.ts` の `lookOf`）。

**指定した色がそのまま画面に出るとは限りません。** 3D の色は照明を通るので、
`AvatarCanvas.tsx` の光の強さとセットで決まります。あそこには2つ仕掛けがあり、
どちらも「指定した色をそのまま出す」ためのものです。

- **トーンマッピングを切ってある**（`flat`）。既定の ACES フィルミックは
  映画向けの曲線で、明るい色ほど灰色へ寄せる
- **光の強さが 1 ではなく 2 前後。** three.js の拡散反射は明るさを π で割るので、
  強さ1の光だと指定した色の 1/3 ほどにしかならず、全体が沈んで見える

色を変えて「思ったより暗い・くすむ」ときは、`look.ts` の数字より先にここを疑ってください。

## 4. 形を直したとき（Blender → アプリ）

`chick.blend` を直しただけでは**アプリの見た目は変わりません。**書き出し直してください。

```sh
"/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b \
    src/avatar/models/chick.blend -P src/avatar/models/export_glb.py
```

書き出しは .blend を読むだけで保存しません。やっているのは3つ（詳細はスクリプトの冒頭）。

- **間引き**。素のままだと約 4MB、間引いて約 0.6MB。アバターは小さくしか出ないので落としてよい
- **塗り分けマスクを頂点カラーで運ぶ**。glTF はノードの Mix を運べない
- カメラ・ライトを落とす。アプリ側（`AvatarCanvas.tsx`）で用意するため

パーツを足したら `export_glb.py` の `RATIOS` にも足すこと。**載っていないものは消えます。**
アーマチュア `Rig`（アニメーションの持ち主）だけは `RATIOS` の外で別に残しています。
間引く対象ではないが、書き出しの選択からは外せないためです。

## 5. どうやって動かしているか

**姿勢の動きは全部 Blender のクリップです。**
`Chick.tsx` は「いまどれを流すか」と「歩いた結果どこへ行くか」を決めるだけで、
時刻から角度や大きさを作るような動きは持っていません。
足の運びや揺れを直したいときは Blender を開きます。

```text
chick.glb の中のクリップ   Walk / Blink / Jump
        │  AnimationMixer が再生
        └─ ボーン（Root / Hips / LegL / LegR / EyeL / EyeR / WingL / WingR / Crest）を動かす

Chick.tsx  pick() … 次にどれを流すか決める
           roam() … 歩いている間、立ち位置と向きを進める
```

### 原理（three.js は何をしているか）

コードに `sin(t)` が1つも無いのに動くので、先にここだけ押さえてください。
**動きの正体は「名前付きのトラックを、重みを付けて足し合わせたもの」**です。

```text
AnimationClip「Walk」          … 1本のクリップ＝トラックの束＋長さ（1.0秒）
  ├ KeyframeTrack "Hips.quaternion"  … 時刻の並び [0, 0.04, …] と値の並び
  ├ KeyframeTrack "Hips.position"
  └ …（ボーンごと・プロパティごとに1本）
        ↓
AnimationMixer（root = rig の <group>）
  トラック名の "Hips" で root 以下のノードを引き当て（getObjectByName と同じ）、
  時刻を挟む2つのキーを補間して、その .quaternion / .position / .scale に**書き込む**
        ↓
AnimationAction … クリップ1本ぶんの再生状態（いまの時刻・ループ・重み）
```

要点は4つです。

1. **トラックはノードの名前で当たる。** Blender 側でボーン名を変えると、
   そのトラックは黙ってどこにも当たらなくなります（エラーは出ません）
2. **書き込むのはボーンの位置・回転・スケールだけ。** 見えている形は、
   そこにぶら下がったメッシュが付いてくる結果です。だから `Chick.tsx` が
   メッシュ側でやっていること（目を潰す・翼を隠す・とさかを拡大する）は
   クリップと喧嘩しません
3. **同じプロパティを複数のアクションが書くと、重み付き平均になります。**
   mixer は書き込みを溜めて、最後に重みの合計で割ります。`Idle` を 0.3、
   `Walk` を 0.7 で流せば、その割合で混ざった姿勢が1つ出ます。
   **重みの合計を1にしておくのはこのため**です（→ 下の「重みの配り方」）
4. **時間を進めるのは毎フレームの `mixer.update(delta)`。** これは
   `useAnimations`（drei）が仕込むので、`Chick.tsx` は書いていません。
   `mixer.timeScale = 0` にすると全クリップの時間だけが止まります

React 側の関わりはごく薄く、**`useAnimations(clips, rig)` が
mixer と `actions`（クリップ名 → AnimationAction）を作るだけ**です。
毎フレームの処理（`useFrame`）は再描画を起こさないので、動いている間
React は何も再レンダーしません。だから立ち位置や重みは state ではなく
`useRef`（`playing.current`）に持っています。

### モデルが持っているクリップ

| クリップ | 長さ | 中身 | 流し方 |
| --- | --- | --- | --- |
| `Idle` | 2.5秒 | 立ち止まり。ゆっくり呼吸し、翼ととさかがわずかに揺れる | ループ。**他が0のとき余りを受け持つ** |
| `Walk` | 1.0秒（2歩） | 足を交互に運び、胴体が上下＋よちよち左右に揺れる。1歩ごとに翼を開き、とさかが遅れて前後左右に振れる | ループ。重みで出し入れする |
| `TurnL` / `TurnR` | 0.67秒 | その場での向き変え。小刻みに足踏みしながら、回る側へ体を傾ける | ループ。重みで出し入れする |
| `Rest` | 3.0秒 | 休憩。お尻で座り、足を前へ・翼をおなかの上へ寄せ、**目を閉じて**深く呼吸する | ループ。重みをゆっくり寄せる |
| `Jump` | 1.25秒 | しゃがむ→翼を開いて跳ぶ→足をたたむ→着地で潰れ、とさかが前に垂れる | 1回きり（`LoopOnce`） |
| `Blink` | 4.0秒 | 4秒に1回、目のボーンを縦に潰す | ループで流しっぱなし |

翼ととさかは**歩き・跳びと同じ周期**で動きます。別々の周期にすると、歩いているのと
関係なくひらひらしているように見えるためです。

**向き変えが左右2本あるのは、傾ける向きが逆だからです。** 傾きだけをコードで
足せば1本で済みますが、それをやると動きの出どころが2つになります（→ 下の約束ごと1）。

**座り込む・立ち上がる動きはモデルに入っていません。** `Idle` と `Rest` は
姿勢がはっきり違うので、重みを寄せる間にその差がそのまま動きになります。
**目もこれと同じ**で、`Rest` は「閉じる動き」ではなく閉じた目を持っているだけ。
座り込む間に重みが寄って、結果としてゆっくり閉じます。

Blender 側のボーンは9本だけです。パーツは**スキニングしていません**。
それぞれのメッシュをボーンに親付けしただけの剛体で、`Chick.tsx` から見ると
モデルの中身は今まで通りただのメッシュのままです（→ [6](#6-いじる時の決まりごと)）。
`Wing_L` / `Wing_R` / `HeadFeather` も、動かすボーン（`WingL` / `WingR` / `Crest`）に
ぶら下がっているだけなので、**ここから大きさを変えたり隠したりする処理はそのまま効きます。**

### どれを流すか（`pick()`）

「立ち止まる → 向き直る → 歩く／跳ぶ／座って休む」を繰り返すだけの状態機械です。

```text
idle ──向きがずれている──> turn ──向き直り終わり──> idle
  │                          ↑                       
  ├──行き先を決めて──────────┘  └──向き直り終わり──> walk ──> idle
  ├──> jump ──> idle
  └──> rest ──> idle
```

- **向きが 0.5 ラジアン以上ずれたら、必ず `turn` を挟みます。** 立ったまま
  ぬるっと回すと足が地面を滑って見えるためです。歩いている最中の微調整は
  ずれが小さいので、そのまま回します
- 活力が低い（`liveliness <= 0.25`）と歩き出さず、座り込んで休みます
- `animate` が false（OSの「視差効果を減らす」）のときは `mixer.timeScale = 0` に
  したうえで、**状態機械ごと止めます。** 重みを寄せ続けると、クリップの時間が
  止まっていても姿勢だけが動いてしまうためです

### 重みの配り方

姿勢のクリップは**全部流しっぱなしで、重みの合計が1**になるように配ります。
`Walk` / `TurnL` / `TurnR` / `Rest` / `Jump` のうち「いまのモードのもの」だけを
1へ寄せ、**余りを `Idle` が受け持ちます。** 立ち止まっている間は自動的に
`Idle` が1になるので、「何も流していない素の姿勢」でひよこが固まることがありません。

寄せる速さはクリップごとに変えています（`RATE`）。休憩は遅く（座り込む間合い）、
ジャンプは速く（しゃがみが薄まらないように）。

### 目は姿勢と別に取り合う

目（`EyeL` / `EyeR`）を書くクリップは `Blink` と `Rest` の2本だけです
（`EYE_CLIPS`）。歩きながらまばたきさせたいので、目は姿勢の取り合いには
入れず、**この2本だけで合計1**にしています。

```text
姿勢  Walk / TurnL / TurnR / Rest / Jump ─ 余りは Idle   合計 1
目    Blink （1 − Rest の重み） ＋ Rest（閉じた目）      合計 1
```

`Rest` の重みぶんだけ `Blink` を下げるのがミソです。**両方を重み1で流すと、
開いた目（1.0）と閉じた目（0.08）が平均されて、半目のまま止まります。**
上の「重み付き平均」（→ 原理3）がそのまま出るところです。

### どこへ歩くか（`roam()`）

Walk クリップ自体はその場の足踏みです。**実際に歩き回らせているのは `roam()`** で、
クリップの重みぶんだけ立ち位置（x, z）を進め、進む方向へ体を向けます。

- 範囲は `ROAM_X` / `ROAM_Z`。端まで来たら中心へ向き直して戻ります。
  **カメラ（`AvatarCanvas.tsx`）や `avatar.css` の比率を変えたら測り直してください**
- 奥行きは遠近で大きさが変わって見えるので、左右より狭くしてあります
- 立ち止まると正面（カメラ向き）に向き直ります。ずれが大きければ
  `pick()` が向き変えのクリップを出します
- 進むのは `weight`（Walk の重み）に比例させています。そうしないと
  歩き出しと止まりぎわに、足が止まったまま滑ります
- 進む方向は `heading`（行きたい方向）ではなく `facing`（いま向いている方向）。
  振り向く途中で横滑りするのを防ぐためです

移動だけは Blender に置けません。クリップに移動を焼き込むと毎回同じ道順になり、
範囲も決められないためです。**姿勢はクリップ、道順はコード**という切り分けです。

### 動かないもの

姿勢と表情は look.ts が決める**状態**なので、クリップではなくそのまま入れます。
時間で変化させない、が決まりです。

| もの | やっていること |
| --- | --- |
| 前かがみ | `look.droop * 0.12` を外側の `group` の `rotation.x` に入れる |
| 目つき | `EYE_SQUASH` の倍率で目を縦に潰す（`look.eye`） |
| 体格 | `look.bodyRadius * SIZE` を `rig` の `scale` に入れる |
| たまご（ステージ0） | モデルが無く球を置いているだけなので、止まったまま |

### 約束ごと2つ

**1. 新しい動きはコードではなく Blender に足す**

`sin(t)` で角度を作るような処理をここに書かないでください（立ち位置を進める
`roam()` だけが例外です。上の通り、道順はモデルに置けません）。
動きの出どころが2つになると、どちらが効いているのか追えなくなります
（以前は浮遊・呼吸・羽ばたきをコードで作っていて、クリップと二重に弾んでいました）。
足すならアクションを1本増やし、`pick()` に流す条件と `POSTURE` への登録だけを
書きます。

**2. クリップは `play()` しっぱなしにして、重みで出し入れする**

歩きを毎回 `play()` / `stop()` すると歩き出しと止まりが瞬間的になります。
ずっと流しておいて `setEffectiveWeight` を 0〜1 に寄せると、自然に歩き出します。
1回きりのジャンプだけは例外で、跳ぶときに `reset().play()` し、
**終わったら必ず `stop()` します**（`clampWhenFinished` のまま放っておくと
最後の姿勢を重み1で押さえ続け、次の歩きと半々に混ざります）。

### ハマりどころ

Blender の書き出しは**どのアクションにも全ボーンのキーを焼きます**。
そのままだと `Blink` にも脚や胴の「素の姿勢」が入っていて、まばたきを重ねた瞬間に
歩きが素の姿勢へ引き戻されます。`Chick.tsx` で**目のトラックを `EYE_CLIPS`
（`Blink` / `Rest`）に、それ以外を姿勢のクリップに振り分けて**から流しています。
Blender 側でボーンを足したり、目を動かすクリップを増やしたりしたら、
この振り分け（`clips` の `useMemo`）と `EYE_CLIPS` を見直してください。

Blender 側の作業で詰まったら [docs/BLENDER_ANIMATION_NOTES.md](docs/BLENDER_ANIMATION_NOTES.md)。

## 6. いじる時の決まりごと

コードを読んでも分からない約束はこの4つだけです。

**1. モデルの中の座標は、実測した定数を使う**

`Chick.tsx` の先頭にある `FOOT_Y` / `HEAD_TOP` / `BODY_R` は chick.glb の実測値です。
マフラーや冠のような「モデルに無いもの」はこれを基準に置きます。
**形を大きく変えたらこの3つも測り直してください。**

**2. パーツの名前でマテリアルを引いている**

色は `Body` / `Beak_Orange` / `Wing_Green` …… というマテリアル名で当てています。
Blender 側で名前を変えると**黙って色が付かなくなります**（エラーは出ません）。

**3. 色は必ずカンマ区切りの `hsl()` で書く**

`hsl(50 80% 70%)`（CSS の新しい書き方）は three.js が解釈できず、**黙って白になります。**
`hsl(50, 80%, 70%)` と書くか、`look.ts` の `hsl()` ヘルパーを通してください。

**4. パーツはボーンに「親付け」する。スキニングしない**

Blender でメッシュをアーマチュアにスキニングすると、three.js 側では
`SkinnedMesh` になります。こうなると
`scene.clone(true)`（アバターを複数出すための複製）がボーンを共有してしまい、
**専用の `SkeletonUtils.clone` に差し替えない限り全部のアバターが同じ動きになります。**
ひよこは独立した塊の寄せ集めなので、剛体のままボーンにぶら下げれば足ります。
おかげで目を潰す（`scale`）・翼を回す・パーツを隠す、といった今までの処理が
そのまま効きます。

ボーン名は**メッシュ名と必ず変えてください**。glTF ではボーンもメッシュも
同じ名前空間に並ぶので、`Body` ボーンと `Body` メッシュがあると
`getObjectByName` とアニメーションのトラック解決が壊れます
（いまは `Root` / `Hips` / `LegL` / `LegR` / `EyeL` / `EyeR`）。

## 7. 表示されるまでを追いかけると

```text
画面が <Avatar lv={3} days={10} vitality={72} variant={0} /> を置く
  ↓
Avatar.tsx  : lookOf(10, 72, 3, 0) を呼ぶ
  ↓
stage.ts    : 10日 → ステージ3（もふもふ）
look.ts     : ステージ3 + 活力72 →
              { bodyRadius: 0.75, bodyColor: 緑, eye: 'open',
                wings: true, crest: false, ... }
  ↓
Avatar.tsx  : WebGLあり → AvatarCanvas を表示
  ↓
AvatarCanvas: カメラと照明を置いて Chick に渡す
  ↓
Chick.tsx   : chick.glb を読む → 緑を塗る → つばさを出し、とさかは隠す
              → ときどき歩き・ジャンプのクリップを流し、4秒に1回まばたきさせる
  ↓
画面に緑のもふもふひよこが表示される
```

### 3D が使えない環境では

アバターは 3D の一種類だけです。WebGL が無い環境と 3D の初期化に失敗した場合は、
同じ比率の空の枠（`.avatar-placeholder`）だけが残ります。アプリは止まらず、
コンソールに `[avatar]` で始まる警告が出るので、原因はそこで分かります。
three.js とモデルは本体とは別に遅延読み込みしているので、読み込み中も同じ枠が出ます。

## 8. なぜこの方式なのか（決定の記録・2026-09-06）

描きたいもの（ステージごとに何が増えるか）を先に決めてから、方式を選びました。
順序が逆になると「描きたい絵が描けない方式」を選んでしまいます。

| 方式 | 利点 | 欠点 |
| --- | --- | --- |
| インライン SVG（採用前の方式） | 出し分けが効き、追加ライブラリ不要 | 複雑な絵は手書きが大変 |
| 画像ファイル（PNG/WebP） | 絵の自由度が最大 | ステージ×活力の枚数ぶん要る（最大35枚） |
| SVG ファイル読込 | ツールで描ける。拡大に強い | パーツ制御は書き出し方しだい |
| Lottie / Rive 等 | 動きが作り込める | **GUI ツールのファイルが要る。描ける人が居ないと1枚も出せない** |
| **3D（react-three-fiber）** ← 採用 | パーツの足し引き・体格の変化・動きが全部できる | three.js のぶん容量が増える |

- **絵を描ける人を待たなくていい。** 一度 Rive を試しましたが、ファイルが用意できるまで
  何も動かせず止まりました
- **「増えるもの」を足すだけでステージが作れる**
- **2軸の掛け合わせが自然に出せる。** 形と色・姿勢が別々の値なので、
  「ステージ6でボロボロ」も自動的に成立する

容量だけが欠点です（three.js は gzip で 250KB ほど、モデルが 0.6MB）。
アバターまわりだけ別チャンクに分けて遅延読み込みしています。

> **その後**: 形だけは Blender で作ったモデルに差し替えました（2026-09-20）。
> 上の判断理由はそのまま活きています。色・表情はいまもコードが決めます。
>
> **さらにその後**: 動きは全部 Blender のクリップに寄せました（2026-09-20）。
> 足を交互に運ぶような動きは、コードから毎フレーム角度を入れるより、
> タイムラインに置いて目で見ながら詰めた方が速く、直すのも Blender の中で済みます。
> コード側に残っていた揺らぎ（浮遊・呼吸・羽ばたき・進化の跳ね）と、
> 光の粒（`Sparkles`）は消しました。**動きの出どころは1つ**という決めです。
