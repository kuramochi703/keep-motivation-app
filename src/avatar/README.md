# アバターの描き方（react-three-fiber）

アバターは three.js（react-three-fiber）で組んだ 3D のひよこです。
モデルファイル（.glb / .vrm）は使わず、球や円錐を並べてコードだけで形を作っています。
VRM を使わないのは、あれが人型（ボーン・表情の規格）前提で、ひよこには合わず、
専用ランタイム（`@pixiv/three-vrm`）と作成ツールが増えるだけになるためです。

---

## ファイルの役割

| ファイル | 中身 | こんな時に触る |
| --- | --- | --- |
| `look.ts` | 「ステージ × 活力」→ 見た目パラメータの対応表 | **色・表情・何段階目で何が生えるかを変えたい** |
| `Chick.tsx` | パラメータを受けて実際に形を組む | **形そのものを変えたい** |
| `stage.ts` | のべ達成日数 → 成長ステージ | 進化に必要な日数を変えたい |
| `AvatarCanvas.tsx` | カメラと照明 | 明るさ・アングルを変えたい |
| `avatar.css` | 表示サイズ | 大きさを変えたい |
| `Avatar.tsx` | 入口。3D を出すか SVG に落とすかを決める | ほぼ触らない |
| `AvatarSvg.tsx` | 3D が使えない時に出る従来の SVG | ほぼ触らない |

## 見た目を決める軸

```text
種類  もりお / だいち / こむぎ  ← 目標設定でユーザーが選ぶ。色相が変わる
軸1  成長ステージ 1〜6         ← 0日からひよこ。のべ達成日数で体格・装備が変わる
軸2  活力 0〜100              ← やれば＋、サボれば−。上下する。   彩度・表情・姿勢が変わる
```

2軸は独立しています。「ステージ6でボロボロ」も「ステージ1で絶好調」も成立するので、
片方を変えてももう片方は壊れません。

一覧はコード側が原典です。ステージの名前・到達日数は `stage.ts` の `STAGES`、
活力のしきい値と表情・装備の条件は `look.ts` の `lookOf`（レベルは `logic.ts` の `levelOf`）。
種類を増やすときは、`logic.ts` の `AVATARS`（名前）と `look.ts` の `VARIANTS`（色相）の
**両方に、同じ並び順で**足してください。並び順が id です。

## いじる時の決まりごと

コードを読んでも分からない約束はこの3つだけです。

**1. 数値はすべて `r`（からだの半径）の倍率で書く**

```tsx
// ◯ ステージが上がって r が変わっても比率が保たれる
<mesh position={[0, r * 1.2, 0]} />
// ✕ ステージ1では合っていても、ステージ6でずれる
<mesh position={[0, 0.9, 0]} />
```

**2. 顔まわりの位置は `faceZ()` を通す**

three.js は物体どうしが重なっても外側だけが見えます。半径 `hr` の頭に顔のパーツを
貼るなら、中心を球の表面まで押し出さないと中に飲み込まれます。パーツが「消える」時は
たいていこれです。`Chick.tsx` の `faceZ()` がその計算をしています。

**3. 色は必ずカンマ区切りの `hsl()` で書く**

`hsl(50 80% 70%)`（CSS の新しい書き方）は three.js が解釈できず、**黙って白になります。**
`hsl(50, 80%, 70%)` と書くか、`look.ts` の `hsl()` ヘルパーを通してください。

## 3D が使えない環境では

WebGL が無い環境と 3D の初期化に失敗した場合は、従来のインライン SVG（`AvatarSvg.tsx`）
に切り替わります。アプリは止まらず、コンソールに `[avatar]` で始まる警告が出ます。
three.js は本体とは別に遅延読み込みしているので、読み込み中の一瞬も SVG が出ます。

## モデルファイル（.glb）に差し替えたくなったら

`Chick.tsx` を `useGLTF` を使うものに差し替え、`look.ts` の値をモデルのモーフや
マテリアルに割り当てます。**`look.ts` の対応表はそのまま使えます。**
