# アバター（3Dのひよこ）

このフォルダだけで完結する説明書です。**上から読めば仕組みが分かり、
下の方に「触る時の決まりごと」があります。**

アプリ全体の話は [README.md](../../README.md)、構成図は
[ARCHITECTURE.md](../../ARCHITECTURE.md) を参照。

---

## 1. ひとことで言うと

**「数値 → 見た目パラメータ → 3Dの形」** という3段階の流れです。

```text
のべ達成日数 ─┐
活力(0〜100) ─┤→  look.ts  →  Look（色・表情・装備の一覧）→  Chick.tsx  → 画面
どのキャラか ─┘   （ただの計算）                              （three.jsで描く）
```

**形**は Blender で作ったモデル（`models/chick.blend` → `chick.glb`）です。
**色・表情・動き**はモデルに入っておらず、コードが決めます。
だから「ステージや活力で見た目がどう変わるか」を直すのに Blender は要りません。

VRM は使いません。あれは人型（ボーン・表情の規格）前提でひよこには合わず、
専用ランタイム（`@pixiv/three-vrm`）が増えるだけになるためです。

## 2. ファイルの役割

| ファイル | 中身 | こんな時に触る |
| --- | --- | --- |
| `look.ts` | 「ステージ × 活力」→ 見た目パラメータの対応表 | **色・表情・何段階目で何が生えるかを変えたい** |
| `Chick.tsx` | モデルを読み、色を塗り、動かす | 動き・パーツの出し入れを変えたい |
| `models/chick.blend` | 形の原典。Blender で編集する | **形そのものを変えたい** |
| `models/chick.glb` | 上を three.js 用に書き出したもの。**手で触らない** | — |
| `models/export_glb.py` | .blend → .glb の書き出し手順 | 書き出す内容を変えたい |
| `stage.ts` | のべ達成日数 → 成長ステージ | 進化に必要な日数を変えたい |
| `AvatarCanvas.tsx` | カメラと照明 | 明るさ・アングルを変えたい |
| `avatar.css` | 表示サイズ | 大きさを変えたい |
| `Avatar.tsx` | 入口。3D の読み込みと失敗時の受け止め | ほぼ触らない |
| `docs/BLENDER_MODELING_NOTES.md` | Blender 作業の失敗と解決策 | モデリングで詰まった時 |

## 3. 見た目を決める軸

```text
種類  もりお / だいち / こむぎ  ← 目標設定でユーザーが選ぶ。色相が変わる
軸1  成長ステージ 1〜6         ← のべ達成日数で体格・装備が変わる。下がらない
軸2  活力 0〜100              ← やれば＋、サボれば−。彩度・表情・姿勢が変わる
```

2軸は独立しています。「ステージ6でボロボロ」も「ステージ1で絶好調」も成立するので、
片方を変えてももう片方は壊れません。

**一覧はコード側が原典です。** ステージの名前・到達日数は `stage.ts` の `STAGES`、
活力のしきい値と表情・装備の条件は `look.ts` の `lookOf`（レベルは `state/logic.ts` の `levelOf`）。
種類を増やすときは、`logic.ts` の `AVATARS`（名前）と `look.ts` の `VARIANTS`（色相）の
**両方に、同じ並び順で**足してください。並び順が id です。

### ステージとモデルの対応

ステージで増えるものは、モデルのパーツを出し入れして表しています（`Chick.tsx`）。

| ステージ | 見た目 | 実体 |
| --- | --- | --- |
| 1 | からだ・あし・くちばし | 常に出ている |
| 2 | つばさ | `Wing_L` / `Wing_R` を表示 |
| 3 | 一回り大きくなる | `look.bodyRadius` |
| 4 | とさか | `HeadFeather` を表示 |
| 5 | マフラー | `Chick.tsx` の `Scarf`（モデルには無い） |
| 6 | 冠 | `Chick.tsx` の `Crown`（モデルには無い） |

表情（`look.eye`）は、モデルの目（球ひとつ）を**縦に潰して**出しています（`EYE_SQUASH`）。
本当に形を変えたければ Blender でシェイプキーを持たせて、潰す代わりにモーフを動かしてください。
ほっぺの赤みはモデルに無いので、いまは出していません。

ステージ0（たまご）はトップページ専用です。モデルではなく球で描いています（`Egg`）。

## 4. 形を直したとき（Blender → アプリ）

`chick.blend` を直しただけでは**アプリの見た目は変わりません。**書き出し直してください。

```sh
"/mnt/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b \
    src/avatar/models/chick.blend -P src/avatar/models/export_glb.py
```

書き出しは .blend を読むだけで保存しません。やっているのは3つ（詳細はスクリプトの冒頭）。

- **間引き**。素のままだと約 4MB、間引いて約 0.6MB。アバターは小さくしか出ないので落としてよい
- **塗り分けマスクを頂点カラーで運ぶ**。glTF はノードの Mix を運べない
- カメラ・ライトを落とす。アプリ側（`AvatarCanvas.tsx`）で用意するため

パーツを足したら `export_glb.py` の `RATIOS` にも足すこと。**載っていないものは消えます。**

## 5. どうやって動かしているか

**動きはすべて `Chick.tsx` の `useFrame` の中**にあります。モデルにはアニメーションの
データ（キーフレームやボーン）が入っていません。毎フレーム呼ばれる関数が、
**経過時刻 `t` から角度や大きさを計算して代入し直しているだけ**です。

動かす相手は2階建てになっています。

```text
<group root>              ← 全身にかかるもの（浮く・前かがみ・進化の跳ね）
  <group rig>             ← モデル本体の入れ物（呼吸・全体の大きさ）
    <primitive model />   ← モデルの中の翼だけ、個別に回す
    マフラー / 冠 / 汗
</group>
<Sparkles> <ContactShadows>   ← 揺れないので外に置く
```

| 動き | やっていること | 効かせる相手 |
| --- | --- | --- |
| ふわふわ浮く | `sin(t * 2.1) * 0.035` | `root.position.y` |
| 呼吸 | 横に `b` 倍、縦に `1/b` 倍（`b = 1 ± 0.03`）。体積を保つので膨らんで見える | `rig.scale` |
| 羽ばたき | `sin(t * 3.4) * 0.3` ラジアン。左右は符号を逆に | `Wing_L` / `Wing_R` |
| 前かがみ | `look.droop * 0.12` に `damp` でゆっくり寄せる | `root.rotation.x` |
| 進化の跳ね | ステージが上がった瞬間に `pop = 1`。減衰させつつ `sin` で一山だけ跳ねる | `root.scale` |
| キラキラ・汗 | 出す／出さないだけ。動きは drei 任せ | `Sparkles` / `Sweat` |
| たまごのゆらぎ | `sin(t * 1.3)` で傾けて、`abs(sin)` で跳ねる | `Egg` |

### 約束ごと3つ

**1. 揺れの大きさは全部 `amp` 倍で束ねる**

```tsx
const amp = animate ? look.liveliness : 0
```

`liveliness` は活力から作った 0〜1 の値です。やつれるとこれが小さくなり、
**どの動きも一斉に小さくなります**。OSの「視差効果を減らす」設定がオンだと
`animate` が false になり、`amp = 0` で全部ぴたりと止まります。
**新しい動きを足すときも必ず `amp` を掛けてください。**

**2. 「今の値を少し足す」のではなく「時刻 `t` から作り直す」**

`position.y += 0.01` のような書き方だと、フレーム落ちした分だけ位相がずれて
アバターごとに動きがバラバラになります。`sin(t * 2.1)` のように時刻から
計算すれば、何が起きてもずれません。

例外は**目標値に寄せたいもの**（前かがみ）です。こちらは `THREE.MathUtils.damp` を
使います。`damp` は経過時間 `delta` を見るので、fps が違っても同じ速さで寄ります。

**3. 翼の角度は上書きせず、モデルの傾きに掛ける**

翼はモデル側ですでに少し傾いています。羽ばたきでその回転を上書きしてしまうと
傾きが消えるので、初回に控えておいた姿勢（`rest`）に羽ばたきを**掛けて**います。
Blender 側で翼の角度を直しても、コードを直さずに済みます。

### ハマりどころ

呼吸で縦に `1/b` 倍すると、そのぶん**足が地面から浮きます**。
`rig.position.y` を毎フレーム押し下げて、足の裏が `y = 0` に残るようにしています。
ここを忘れると、呼吸に合わせてひよこが上下して見えます。

## 6. いじる時の決まりごと

コードを読んでも分からない約束はこの3つだけです。

**1. モデルの中の座標は、実測した定数を使う**

`Chick.tsx` の先頭にある `FOOT_Y` / `HEAD_TOP` / `BODY_R` は chick.glb の実測値です。
マフラーや冠のような「モデルに無いもの」はこれを基準に置きます。
**形を大きく変えたらこの3つも測り直してください。**

**2. パーツの名前でマテリアルを引いている**

色は `Body` / `Beak_Orange` / `Wing_Green` …… というマテリアル名で当てています。
Blender 側で名前を変えると**黙って色が付かなくなります**（エラーは出ません）。

**3. 色は必ずカンマ区切りの `hsl()` で書く**

`hsl(50 80% 70%)`（CSS の新しい書き方）は three.js が解釈できず、**黙って白になります。**
`hsl(50, 80%, 70%)` と書くか、`look.ts` の `hsl()` ヘルパーを通してください。

## 7. 表示されるまでを追いかけると

```text
画面が <Avatar lv={3} days={10} vitality={72} variant={0} /> を置く
  ↓
Avatar.tsx  : lookOf(10, 72, 3, 0) を呼ぶ
  ↓
stage.ts    : 10日 → ステージ3（もふもふ）
look.ts     : ステージ3 + 活力72 →
              { bodyRadius: 0.75, bodyColor: 緑, eye: 'open',
                wings: true, crest: false, ... }
  ↓
Avatar.tsx  : WebGLあり → AvatarCanvas を表示
  ↓
AvatarCanvas: カメラと照明を置いて Chick に渡す
  ↓
Chick.tsx   : chick.glb を読む → 緑を塗る → つばさを出し、とさかは隠す
              → 毎フレーム、浮かせて呼吸させて羽ばたかせる
  ↓
画面に緑のもふもふひよこが表示される
```

### 3D が使えない環境では

アバターは 3D の一種類だけです。WebGL が無い環境と 3D の初期化に失敗した場合は、
同じ比率の空の枠（`.avatar-placeholder`）だけが残ります。アプリは止まらず、
コンソールに `[avatar]` で始まる警告が出るので、原因はそこで分かります。
three.js とモデルは本体とは別に遅延読み込みしているので、読み込み中も同じ枠が出ます。

## 8. なぜこの方式なのか（決定の記録・2026-09-06）

描きたいもの（ステージごとに何が増えるか）を先に決めてから、方式を選びました。
順序が逆になると「描きたい絵が描けない方式」を選んでしまいます。

| 方式 | 利点 | 欠点 |
| --- | --- | --- |
| インライン SVG（採用前の方式） | 出し分けが効き、追加ライブラリ不要 | 複雑な絵は手書きが大変 |
| 画像ファイル（PNG/WebP） | 絵の自由度が最大 | ステージ×活力の枚数ぶん要る（最大35枚） |
| SVG ファイル読込 | ツールで描ける。拡大に強い | パーツ制御は書き出し方しだい |
| Lottie / Rive 等 | 動きが作り込める | **GUI ツールのファイルが要る。描ける人が居ないと1枚も出せない** |
| **3D（react-three-fiber）** ← 採用 | パーツの足し引き・体格の変化・動きが全部できる | three.js のぶん容量が増える |

- **絵を描ける人を待たなくていい。** 一度 Rive を試しましたが、ファイルが用意できるまで
  何も動かせず止まりました
- **「増えるもの」を足すだけでステージが作れる**
- **2軸の掛け合わせが自然に出せる。** 形と色・姿勢が別々の値なので、
  「ステージ6でボロボロ」も自動的に成立する

容量だけが欠点です（three.js は gzip で 250KB ほど、モデルが 0.6MB）。
アバターまわりだけ別チャンクに分けて遅延読み込みしています。

> **その後**: 形だけは Blender で作ったモデルに差し替えました（2026-09-20）。
> 上の判断理由はそのまま活きています。色・表情・動きはいまもコードが決めていて、
> モデルは形しか持っていません。
